### 现状盘点、C++ 依赖脱钩三阶段路线与 `huaBin` 定位（2026-11-27）

**当前代码体量与归属水位**：C++ `108` 文件约 `25,616` 行（`src/` + `include/hua/`）；自举 Hua 源码 `36` 文件约 `11,124` 行（`selfhost/`）；纯 Hua 标准库 `2` 文件 `176` 行（`std/alg_integer.hua`、`std/sse.hua`）。词法器、模块/包解析、C04 能力分析、HUAB 归档生成器、原生 C++ 生成器与 N3 发布驱动均已有纯 Hua 实现并达成 `G1 == G2`、`C2 == C3` 不动点；剩余 C++ 依赖分为三道锁：
1. **历史 C++ 前端脚手架（~9,500 行，可退役）**：`lexer/parser/sema/bytecode/native.cpp`，因 `selfhost/` 尚差固有方法、`interface`、用户泛型、`@test` 而暂留为默认 `hua run/check/test` 与语义对照。
2. **原生后端借用 C++ 工具链**：`hua-generator.exe` 当前吐出 C++20 文本，依赖随包 Clang/lld 与 `native_rt.hpp`/`libhua_semantics.a`。
3. **底层运行时内核（~16,000 行）**：VM、GC、Task 纤程调度、OS 适配（Win32/WinHTTP）及 30 个内建标准库，因普通 Hua 语言刻意不开放裸指针与直接 OS 系统调用。

**脱离 C++ 依赖的三阶段演进路线**（最终目标：语言自身 100% 构建与演进，C++ 与 Python 仅作为 Native ABI v2 外部扩展包接入）：
- **阶段 1（前端统一 + 标准库纯 Hua 化 + 重组件外置）**：补齐 `selfhost/` 剩余语法与 5D 标准库映射，用 Hua 重写 `hua` CLI 主入口并退役 C++ 前端；将纯逻辑标准库迁入 `std/*.hua`；将 Wasmtime、Python Bridge、SQLite 等重型组件完全外置为可选 ABI v2 包。
- **阶段 2（自研轻量原生机器码后端）**：`selfhost/` 从 IR 直接生成 x86_64/ARM64 机器码并写出 PE/ELF/Mach-O，彻底摘除 C++ 中间代码、PCH 与随包 Clang/lld，使 `huaBin` 降至数 MB 级且冷构建进入百毫秒级。
- **阶段 3（内部系统方言 + 纯 Hua Runtime/VM）**：仅对 `@sdk/src/runtime/` 内部开放受控内存布局、指针读写与 OS 动态库/syscall 声明（业务层 Hua 保持 100% 内存安全），用 Hua 自身重写 GC、调度器、OS 适配与 `.huab` VM，实现源码仓 0 行 C++。

**`huaBin/` 的核心定位**：对外是零前置依赖、跨机器解压即用的**官方便携 SDK**；对内是语言脱离 C++ 后跨代自我繁殖（用上一代 `huaBin` 编译下一代 `huaBin`）的**活体种子库（Living Seed）**。其纯化标尺直观可见：当 `huaBin/` 中不再包含 `include/*.hpp`、`libhua_semantics.a` 与 `toolchain/clang++`，且 `bin/hua.exe` 本身亦由 `src/` 下 `.hua` 源码直接编译产出时，即达成 100% 纯 Hua 自举闭环。详见[完整分析记录](../.codex-sync/knowledge/bootstrap-performance/designs/2026-11-27-step5-decoupling-and-asm-vm-analysis.md)。

### huaBin 目标目录与生成责任

仓库中的 `huaBin/` 由装配脚本生成。Windows 原生 SDK 已交付宿主、两种原生编译器、Hua 源码、种子、编译工具与运行库。外部包随对应能力交付。开发仓维护权威源码，装配时按清单复制；用户可在 SDK 中修改 Hua 源码并重建到独立目录，校验通过后再提升为新种子。

~~~text
huaBin/
  bin/                    hua.exe 和装载所需的 Windows DLL
  src/compiler/           来自 selfhost/ 的 .hua 源码闭包
  src/std/                从开发仓 std/ 装配的纯 Hua 标准模块
  lib/bootstrap/          compiler.huab 种子
  lib/compiler/           Hua 原生生成器、归档编译器与发布驱动
  lib/windows-x86_64/     Windows 原生链接所需静态库
  include/                原生编译所需的运行时头文件
  toolchain/              固定 Clang/lld 及逐文件清单
  packages/               可选包的 .hua 包装、.huam 和平台库
  examples/               可构建和运行的示例
  manifest.json           文件来源、生产者、版本、目标、ABI、依赖及哈希
  licenses/               随包组件许可证
~~~

现有 SDK 编译入口从自身位置发现宿主和种子。SDK 根覆盖与标准模块清单校验随标准源码模块解析推进。项目模块、受保护的标准模块、显式外部包分别解析。生成的中间 C++ 和缓存放构建目录，需随包交付的少量 C++/Python 源码归对应包。[现有安装器](../scripts/install-local.ps1)

### 自举性能与停止条件

每次完整编译沿用 **600 秒墙钟上限**。C1 是宿主从冻结源码构建的种子，C2 是 C1 对同源的输出，C3 是 C2 再编译同源的输出。计时分别记录种子准备、执行和发布；VM 步数、阶段工作量与套件等待时间分别报告。首次超时、预算耗尽或产物不一致即停止该负载，保存输入、工具身份、失败阶段和可用计数，定位原因后再决定是否复测。优化前后复验 A07 的能力、首错和产物；实验是否进入默认路径以真实负载数据决定。[机器合同](../selfhost/contract.json) · [性能实施方案](VM与自举性能改造分析.md#selfhost-performance-plan)

## 已确认合同与查阅入口

- **语言原则。** 小核心、静态类型、显式转换，使用 struct、method、interface 和组合。沿用 `#` 行注释及可嵌套的 `#* … *#`，`/` 真除、`//` 向下整除。数值、绑定、只读/可写及清理沿用已发布语义。[语言设计与类型规则](语言设计与类型规则.md)
- **编译与产物。** 普通产物与 Error/void、File 等能力按版本门禁。HUAB 保存程序，活资源与协程由运行时管理。错误、预算、元数据和加载校验须跨执行路径一致。[产物合同](运行时与扩展设计.md#e0-artifact-contract) · [预算合同](运行时与扩展设计.md#e0-budget-contract)

### ER-DEC-01–08 · 错误基础

默认 `Result<T>` 使用 string 错误；`Result<void,E>` 允许无载荷成功。标准 Error 是名义只读值，程序以 domain 和 code 判断身份；原因链有界，上下文返回新值。旧 string 通过显式适配保留消息，传播时不自动打印。新增系统接口逐项盘点，现有签名保持兼容。[八项确认原文](../.codex-sync/knowledge/planning/2026-11-18-consolidation/originals/设计决策与未决事项.md#error-foundation-review) · [现行 Error 接口](标准库与内建接口.md#standard-error-contract)
