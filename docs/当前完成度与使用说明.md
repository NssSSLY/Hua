## 1. 当前完成到哪里

已经打通“源码 → 解析 → 基础语义检查 → 编译为字节码 → VM 执行”的完整链路。
可以写、检查、运行基础 Hua 程序，拆分本地模块，保存为 `.huab` 后运行，并调用 Native/WASM 扩展。
现在还可运行独立异步任务、取消/超时和任务组，进行受检查的数组并行，并使用 SSE2 数组加减乘；专用 GC 支持循环回收。
现在也可以接收命令行参数和标准输入，读写 UTF-8 文本文件，处理字符串与 JSON 数据；也可读写任意二进制文件，增长同质列表并用缓冲生成二进制数据。
可选 Python Bridge 可导入 Python 包、调用函数与对象，现已实测第三方 packaging；核心不依赖 Python。
项目已从语言设计文档发展为可执行的语言原型。
已补齐Windows本地安装/PATH脚本与VS Code基础插件；Hua编写的词法器能扫描自身源码，完整自举编译器仍待后续。

## 2. 现在可以做什么

| 用途 | 可以怎样做 | 适用范围 |
|---|---|---|
| 学习 Hua 与做算法练习 | 写 `.hua`，运行函数、递归、循环、数组/Slice | 数学计算、查找、基础数据处理 |
| 编写小型数据处理脚本 | 参数/标准输入、UTF-8 文件、字符串、JSON，以及既有语言结构 | 同步文本处理；网络/数据库尚未开放 |
| 拆分代码为模块 | 在入口目录下建立 `.hua` 或 `package.hua`，使用 import/as/pub | 本地项目；不从远端下载依赖 |
| 保存可执行字节码 | `hua build` 生成 `.huab`，再用 `hua run` 运行 | 仍需要 Hua 运行程序，不生成 `.exe` |
| 调用 C/C++ 扩展 | 提供 `.huam` 清单和同名动态库 | bool/int/float/string 参数、相应结果或 void |
| 调用 WASM 扩展 | 放置导出数值函数的 `.wasm`，使用 import | 当前不支持 WASM 字符串/容器 ABI 或外部 imports |
| 调用 Python 生态 | 可选构建、import python as py、py.import_module / getattr / call | 已验证 math、项目类与 packaging；具体包需单独验收，部署仍要 CPython/包 |
| 编辑与运行项目 | 安装PATH后终端hua run，VS Code基础插件检查/运行/生成HUAB | 运行使用现有VM；HUAB不是独立exe，暂无LSP/调试器 |
| 并发数据处理 | async、Task<T>/await、taskgroup、std.task 和 parallel for | 独立快照，不共享可写对象；文件仍同步，取消采用协作规则 |
| 数值向量计算 | std.simd.add/sub/mul 处理 f32/f64/float 数组 | 本机 SSE2；通用 simd for 仍是受检查提示 |
| 检查和调试 | check 检查；ast 看语法树；bytecode 看指令；interpret 作对照 | 有源文件/行列定位及部分错误提示 |

现阶段主要适合语言开发、算法学习及小型计算程序。
当前可编写文本文件与 JSON 自动化脚本；HTTP 服务、数据库应用、AI Agent 与完整系统程序仍需要后续标准库和运行时能力。
Native 可以提供额外能力；现有 Python Bridge 可使用兼容的 Python 包，遵守同进程执行及外部依赖限制。Hua 自有 HTTP/数据库库尚未实现。

## 4. 写第一个 Hua 程序

[examples/quickstart.hua](../examples/quickstart.hua) 的完整内容是：

```hua
# Hua 入门：函数、循环、变量和除法
fn add(a int, b int) int {
    return a + b
}

fn main() {
    var total = 0
    for i in 0..5 {
        total += i
    }
    print("Hua", add(20, 22))
    print(total)
    print(7 / 2, 7 // 2, 7 % 2)
}
```

`0..5` 包含 0、不包含 5；因此 total 为 10。
`fn main()` 是可选的零参数入口，执行器先完成模块与顶层初始化，再自动调用它。
`let` 不可重新绑定，`var` 可修改，`const` 当前仅做支持范围内的编译期标量计算。
声明目前必须初始化。函数参数和返回值可写类型注解；普通 int/float 混算需要显式转换。

运算与注释要点：

| 写法 | 含义 |
|---|---|
| `7 / 2` | 3.5，真除法 |
| `7 // 2` | 3，int 整除；`-5 // 2` 为 -3 |
| `7 % 2` | 1；负数余数与整除共同满足对应公式 |
| `2 ** 3` | 8，幂；幂右结合 |
| `# 注释` | 单行注释 |
| `#* 内容 *#` | 可嵌套块注释 |
| `##` / `#** ... **#` | 文档标记预留，当前按注释跳过 |

`//` 始终是整除，`/* ... */` 不是注释。文件首行 `#!` 可用作 shebang。
更多例子见 [fibonacci](../examples/fibonacci.hua)、[struct](../examples/struct.hua)、[binary_search](../examples/binary_search.hua)、[comments](../examples/comments.hua)。

### Map、多个结果与可恢复错误

完整可运行代码见 [values.hua](../examples/values.hua)，逐项冻结规则见 [Phase 5](第五阶段_映射多返回与结果语义.md)。

```powershell
.\build\hua.exe run .\examples\values.hua
.\build\hua.exe interpret .\examples\values.hua
.\build\hua.exe build .\examples\values.hua -o .\build\values.huab
.\build\hua.exe run .\build\values.huab
```

三种运行方式均输出：

```text
2 true nil
11
1 3
ok(5) err(division by zero)
true 4 true
```

Map 缺失键为 nil；先用局部 let 绑定，再 `!=nil` 检查或 unwrap。`has` 可区分值为 nil 和不存在。
`let/var a,b=f()` 接收多个结果，`a,b=b,a` 交换；`_` 丢弃。全部 RHS 计算/检查完成后才写入目标。
Result<T> 默认为字符串错误；`?` 在返回 Result 的函数中提前传播 Err。unwrap_or 的默认参数总会立即求值。
Map/Result 解包后的只读能力不能通过 var 别名提升；需要独立修改时 clone。函数结果写能力暂不跨函数推断。
Optional<Result> 和 Map 的直接 Result 值暂不支持；完整控制流收窄、通用 Tuple 和容器结构比较仍待设计。

### 从输入和文件处理 JSON

```powershell
'hello' | .\build\hua.exe run .\examples\standard_library.hua -- .\examples\data\profile.json
'hello' | .\build\hua.exe interpret .\examples\standard_library.hua -- .\examples\data\profile.json
.\build\hua.exe build .\examples\standard_library.hua -o .\build\standard_library.huab
'hello' | .\build\hua.exe run .\build\standard_library.huab -- .\examples\data\profile.json
```

输出 `HUA:3:hello`；[完整示例](../examples/standard_library.hua) 使用 os.args 获取路径、fs.read_text 读取文件、json.decode/get/as_* 获取数据，
再由 io.read_line 读取一行和 strings.upper_ascii 转换名字。数据路径相对启动工作目录，源码导入规则仍相对入口目录。
stdin 的 EOF 是 Ok(nil)，空行是 Ok("")；JSON null 使用 json.is_null 检测。
输入/文件/JSON 的可恢复错误统一为 Result；纯字符串函数返回常规值，资源超限可报 E4099。
37 个函数的签名和冻结边界见 [Phase 6](第六阶段_程序输入与基础标准库.md)。

## 5. 常用命令

以下命令在项目根执行；把示例路径换成自己的文件即可：

| 目的 | 命令 |
|---|---|
| 查看帮助 | `.\build\hua.exe help` |
| 查看版本 | `.\build\hua.exe version` |
| 检查完整源码依赖图 | `.\build\hua.exe check .\examples\quickstart.hua` |
| 运行源码，默认用 VM | `.\build\hua.exe run .\examples\quickstart.hua` |
| 使用原解释器作对照 | `.\build\hua.exe interpret .\examples\quickstart.hua` |
| 打印当前文件语法树 | `.\build\hua.exe ast .\examples\quickstart.hua` |
| 显示编译后的指令 | `.\build\hua.exe bytecode .\examples\quickstart.hua` |
| 输出指定 HUAB 文件 | `.\build\hua.exe build .\examples\quickstart.hua -o .\build\quickstart.huab` |
| 校验 HUAB | `.\build\hua.exe check .\build\quickstart.huab` |
| 运行 HUAB | `.\build\hua.exe run .\build\quickstart.huab` |

`build file.hua` 默认输出同名 `.huab`，也可以用 `-o` 指定路径；输出扩展名须为 `.huab`。
`bytecode` 也接受 HUAB；`ast`、`interpret`、`build` 不接受 HUAB 输入。
check/build 不执行程序初始化。check 源码会检查依赖图；check HUAB 校验文件与指令，不重新证明完整源码语义。
退出码：0 成功，1 读取/检查/执行错误，2 命令用法错误。
当前没有交互 REPL；run/interpret 使用 `--` 传递程序参数，`.huab` run 同样支持。

## 6. 使用模块、Native 和 WASM

### 本地 Hua 模块

```powershell
.\build\hua.exe run .\examples\modules\main.hua
```

输出 `5`，然后 `4 6`。入口通过 `import geometry as geo` 导入同目录下的 geometry/package.hua。
在入口目录下放置模块，通过 `pub fn` / `pub struct` / `pub` 方法公开接口；普通未公开声明不可跨模块访问。

`import a.b` 的查找顺序固定：`a/b.hua` → `a/b/package.hua` → `a/b.huam` →
`a/b/package.huam` → `a/b.wasm` → `a/b/package.wasm`。
解析根固定为入口源码目录。重复导入与菱形依赖共用实例；循环导入拒绝；依赖 main 不自动调用。

### Native/WASM 演示

先完成本机构建，再执行：

```powershell
.\build\hua.exe run .\build\extensions\main.hua
.\build\hua.exe build .\build\extensions\main.hua
.\build\hua.exe run .\build\extensions\main.huab
```

两种运行方式都输出：

```text
42 42
hello Hua true
5 7
```

演示分别调用 C++ native_math 与 WASM wasm_math 的导出函数。
构建会生成示例 DLL 与 WASM 文件；Python 用于 WAT 转换和 CLI 测试。

自己做 Native 扩展时，用 [include/hua/native.h](../include/hua/native.h) 实现 C 入口与导出描述符，
再写同名 `.huam` 清单，例如首行 `HUA_NATIVE 1` 后接 `pub fn add(a int,b int) int {}`。
清单中的函数名、参数和结果类型须与动态库一致；Windows 同名库为 `.dll`。
当前清单最多 32 个参数、0 或 1 个结果，不能自动传递 struct、Slice、Map 或 ref/ptr。
Native 句柄与字符串视图只在本次调用有效；Native 是可信的同进程代码。

自己做 WASM 扩展时，导出 i32/i64/f32/f64 函数并放在解析根内；通过 import 使用导出名。
当前拒绝 WASI 和其他 host/module imports，以及公开引用/vector 签名和多返回。
每实例包括 start 与后续调用共享 1,000,000 fuel，线性内存上限 64 MiB。
完整操作、C 接口例子与 WASM 边界见 [Phase 4 扩展说明](第四阶段_字节码文件与扩展.md)。

## 7. 发布自己的程序

纯 Hua 程序的 Windows 发布目录至少需要：

```text
发布目录/
  hua.exe
  wasmtime.dll
  wasmtime-LICENSE.txt
  app.huab
```

在发布目录运行 `hua.exe run app.huab`。HUAB 包含整个程序的代码与诊断来源，运行时不需要原 `.hua`。
WASM 字节也会嵌入 HUAB；Native 动态库需另带，保持原入口根内的相对路径。
即使只运行纯 Hua 程序，当前 Windows 构建也需要 wasmtime.dll。
用 `-o` 输出到新目录不会复制 Native DLL。对应 ABI/架构与 DLL 的额外依赖也必须匹配。

HUAB 仍依赖 Hua VM，并不生成独立 EXE；它保留源码文本，不能用来隐藏源码。
CRC32 检测损坏，不提供签名或来源认证；结构验证不是恶意 Native 插件的沙箱。
当前发布部署只验证了 Windows x64，其他平台不标记为已验证。

## 8. 从 GitHub 克隆后怎样构建

GitHub 保存源码、测试、规范与文档，不携带 `.tools/` 工具包、`build*/` 或生成的 `.huab`。
克隆后必须准备 C++20 编译器、CMake 3.20+、Ninja、Wasmtime C API SDK；完整示例与 CLI 测试还需要 Python。
可用 SDK 版本和本机路径说明见 [Phase 4 依赖记录](第四阶段_字节码文件与扩展.md#依赖记录与验收)。

以下为 Windows LLVM-MinGW/Ninja 构建示意：**把两处工具路径换成实际安装目录**，并确保 cmake/ninja/Python 可以被找到。

```powershell
git clone https://github.com/NssSSLY/Hua.git
Set-Location Hua
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER="C:/工具目录/bin/clang++.exe" -DWASMTIME_ROOT="C:/Wasmtime-SDK目录"
cmake --build build
ctest --test-dir build --output-on-failure
.\build\hua.exe run .\examples\quickstart.hua
```

Wasmtime-SDK 目录应包含 include/wasmtime.h、lib/wasmtime.dll、lib/wasmtime.dll.lib 与 LICENSE。
本机 scripts/build.ps1 的便携工具路径不会在克隆时自动出现。
以上说明以当前实测工具链为基线；MSVC、其他系统与其他 SDK 版本仍需要单独验证。
