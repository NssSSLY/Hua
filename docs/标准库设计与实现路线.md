## 当前主线：性能优先的标准库对齐（2026-10-23用户决定，候选清单）

**决定**：暂不推进自举任务；在优先考虑性能的前提下完善标准库，常用方法基本与成熟语言（Python、Go、Rust、JavaScript）对齐。本节只列待办与顺序，**下表所有函数均为候选，未实现、不可调用**；开始某一切片前再冻结精确签名、错误、容量与复制/能力规则，并写入[标准库与内建接口](标准库与内建接口.md)。对应固定待办为[HUA-D038](设计决策与未决事项.md#design-backlog)。

### 性能原则（每个切片都要满足）

1. **热点操作一次原生调用完成**：字符串、容器、编码、哈希等逐元素工作在C++宿主内完成，Hua侧只计一次调用的指令步数；每次调用设元素/字节工作上限（沿用`std.alg`的32,000,000）并每1024项做取消检查。纯算法组合可用Hua源码实现，但不得把O(n)循环留在热路径上。
2. **不做隐藏复制**：只读结果能共享就不复制（返回只读Slice/视图）；需要修改的提供显式`mut`版本；map查找不复制键。复制语义仍遵守现有值语义与能力合同。
3. **先有基准再实现**：每个切片在`perf/bench/`加同算法微基准与`perf/reference/`的CPython/Lua对照程序，验收时与CPython/Lua同机对比，并用`ab_bench`确认既有基准无退化。
4. **纯函数＋mut版本成对**：与Hua值语义一致；不引入隐式int/float混算。
5. **兼容**：新函数登记`since`，按批次升级HUAB格式；旧运行时明确拒绝。

两项变慢是形态所致，不是退化：`sorted_by`需n log n次回调（5000项约6万次），手写把键压进int后走原生排序不回调，**按键版本`sorted_by_key`快5倍，文档推荐用它**；`update`每个元素都执行一次Hua函数调用，而手写版不调用任何函数——与同样调用`inc`的手写`m[w]=inc(maps.get_or(m,w,0))`相比慢约1.13倍（0.306→0.346秒），余量是一次回调重入（三个协程帧）的固定开销。

实施中的性能处理（同构建交替计时）：`update`初版0.421秒；回调标准函数在`Op::Call`处直接执行（省去`call()`协程与带锁的`builtin_info`查找）、宿主不复制整条Instruction→0.360；`callback_shape`不再为参数分配类型串→持平；为`Routine`加每线程协程帧池→无变化，**已回退**；回调复用标准调用点自身闲置的FunctionRoute缓存（免`function_layout`/`code_layout`哈希与按名插参）→0.346，`fold`0.154→0.137。修正一处由此引入的缺陷：带route的回调帧原指向宿主内的span，错误展开时宿主先析构，VM补“called from”时悬空崩溃（深递归超128层时0xC0000005）；改为指向字节码中标准调用的span（无则复制），E4099恢复正常。

正确性：`tests/callbacks_l01_tests.py`（57项：三路径、空输入/短路/稳定性/ALG_EMPTY、回调诊断传播、调用深度、E5三种就地函数、静态E3005/E3004/E3003、HUAB11头部与降级E6002）；`er0_inventory`新增ER0-V01–V15组。回归：`ab_bench`对切片2构建core 0.94–1.03x（05_map_ops 0.94x经交替三方计时〔含更早构建〕为波动），既有stdlib基准0.95–1.17x；75项CTest中74项通过，`archives_extensions`为HUA-D037既有本机问题；自举C2与记录逐字节相同（f73869fa…，1,281,255,218步）。

## 设计结论

Hua采用三层：小而稳定的语言Core、随发行版提供的标准库、独立版本的可选包。重点覆盖算法、自举基础及Agent共享的JSON、HTTP、任务/取消、进程和互操作。普通核心安装即可使用已发布的标准接口，Python用于早期补充生态，核心不依赖它。

“标准”指接口、分发、兼容和验收责任，不要求每个函数写进C++。宿主操作/性能原语放共享运行时，纯算法与组合尽量用Hua源码实现；源码分发与Resolver还需设计。保留std.alg、std.strings、std.task等名字，不照搬参考回答的algo/string/async，也不增加另一套裸import json/http写法。

官方优先维护一个**可选SQLite包**满足本地状态存储；数据库驱动不成为默认核心依赖。先证明SQLite连接/事务模型，再评估通用数据库接口，不预先宣布std.sql或建设ORM。JSON、HTTP、任务、process是稳定标准方向；完整FFI/binding需要兼容设计，不以“标准化”名义一次扩展ABI1。

## 所有新接口的共同约束

- 命名：沿用std.*，避免同义入口。开始实现前写精确参数/返回声明；候选表不视作可运行API。
- 类型：不引入隐式int/float混算或任意精确数值提升；T/K范围明确。首版排序容器先限定已支持标量或显式priority，用户泛型约束另定。
- 可变性：纯操作返回独立只读值/明确快照；就地修改须mut。明确深复制、嵌套共享、只读能力和失败后内容。
- 错误：保留Result<T,string>等旧合同；新增接口给可识别错误前缀/码。结构化Error另做兼容扩展，不一次更换全库返回类型。业务/系统Err与预算/取消诊断分开。
- 资源：每项给单次字节/元素、深度/工作量、输出/并发上限；既有16MiB文本、128MiB字节、百万元素不自动提高。原生长循环响应取消，不能只靠VM步数约束。
- 句柄：close/defer是及时释放主路径，GC不代替及时关闭。明确关闭后使用、重复close、借用/转移、线程所属和Task快照。
- 时间：Duration明确单位，Deadline用本进程单调时钟，现实时间用于日志/恢复；保留软超时清理延迟，未实现I/O中断就不承诺硬截止。
- 兼容：引用登记since并验证旧运行时拒绝；只有实际编码/布局改变才升级HUAB/ABI。包版本与HUAB版本分别管理。
- 依赖：Core不依赖Python；TLS/哈希/压缩使用验证过的后端，记录许可证、平台和分发依赖，不自行设计TLS。

### S2：算法、统计、随机、编码

优先gcd/lcm/位计数、unique/chunk、mean/variance/stddev/median/quantile、seed PRNG/shuffle/sample、hex/base64/SHA-256，每次只选一个模块或小组。

冻结空输入、ddof/样本与总体方差、quantile插值、重复项顺序、有限数值/溢出/舍入。统计用确定性順序或稳定求和，不能并行后改变合同。PRNG按实例持有状态、公开算法/版本并给固定seed向量；OS安全随机另列，PRNG不能冒充安全凭证来源。

sort_by/filter/map/fold先补两执行器一致的Hua回调入口，覆盖预算、Result/诊断、GC根、取消、捕获、重入；已有闭包不等于标准函数可回调。惰性迭代、泛型约束、精确数值重载另定。

停止条件：独立参考算法、随机容器序列、固定seed向量、数值误差/资源证据；top-k、BFS/拓扑工作流例子可运行。图算法优先写Hua，分发未完成前作为普通项目模块证明，不声称可全局导入。

### S3：资源句柄、流与取消底座

D002-a内部底座与D002-b同步File均已实现并验收。std.file的12接口、File/IOFailure、模式/EOF/部分进展/flush/close、逻辑Task域、GC宿主回收、嵌套边界拒绝和AST/VM/无源码HUAB8对照见 [同步File合同](运行时与扩展设计.md#d002-file-runtime)。File默认层级额度已定；公共配置、E5异步与真实网络/Device后续分别验收。

File的open/read/write/seek/tell/flush/close/state/close_error已可用；Reader/Writer、context/deadline、队列/信号量及可取消读写仍候选。先定线程所属/转移；不得把宿主句柄盲目深复制成两份所有者，无法安全转移时明确拒绝跨任务传递。

流读写采用Bytes，文本做UTF-8增量解码，明确EOF/空片段。写入返回实际字节或另有write_all，部分失败可观察；管道/响应有背压与上限。I/O事件循环按E5/N2另实现，不先随意改变当前async语义；控制块与HostBuffer/Event复用E6a，低复制租约不得绕过Task深快照。

停止条件：close/重复close/错误defer、取消释放、分片/seek/EOF、关闭后拒绝、Task快照拒绝或正确转移；两执行器与HUAB中创建资源一致。HUAB不保存活跃句柄；资源关闭不依赖GC及时性。

### S4：原生HTTP/HTTPS，再流式模型通信

std.url解析/编码；std.http候选Client/Request/Response。先有界完整响应GET/POST、headers、Bytes/JSON、状态码、显式timeout/cancel，再Reader流、UTF-8分片/SSE。

冻结连接/读取/总deadline、重定向/认证头、TLS证书与主机名验证、响应上限/错误分类。建议传输失败Err，HTTP非2xx仍返回Response供业务判断；实现前正式冻结。默认不重试有副作用请求，重试预算/幂等性放组合库。

停止条件：本地HTTP/TLS固定服务覆盖成功、4xx/5xx、延迟/断连/取消、超限/证书失败；流拆包、背压、提前close/清理。无需模型密钥；server/socket/WebSocket后续独立验收。SSE可以基于HTTP/1.1，不把HTTP/2或QUIC作为首个模型客户端前提；新增异步接口依赖E5/N2的真实恢复。

### S5：进程与可选SQLite

process用可执行文件+参数数组、显式cwd/env、exit_code、有界stdout/stderr与管道。shell执行作为另一显式能力；冻结后代进程清理、取消/超时、管道死锁、编码与部分输出。

可选SQLite包先open/close、绑定参数execute/query、begin/commit/rollback。SqlValue建议具名enum，不靠JSON把所有SQL数值变float；明确NULL、int64/real/text/blob、线程所属、busy/取消和结果集关闭。参数不拼SQL，GC不负责事务提交。

停止条件：临时子进程/数据库，输出/退出/超时回收、引号/中文参数、SQL参数注入反例、失败回滚、关闭后拒绝；无Python核心仍运行。SQLite证明后才评估公共数据库抽象和更多驱动，不预建ORM。

### S6：最小Agent包，再协议/检索

Agent/LLM/MCP独立包。首版消息、显式工具注册、参数校验、有限轮次执行、会话/检查点、取消/预算与trace；模型依赖HTTP，工具用本地Hua/process或前台Bridge。

离线模型替身先跑“读配置→消息→模型响应/工具请求→校验→调用→保存→下一轮/结束”，覆盖工具失败/重试/恢复。限制轮数、工具次数/并发、deadline与输出；token/费用只有可验证计量才宣称准确。trace不默认打印凭证。

MCP/JSON-RPC、Schema、SSE、供应商SDK各自固定协议版本与子集后测试；能解析JSON不代表协议兼容。后续重试/限流/幂等、录制重放/评测、切分/BM25/embedding/向量存储，再做多Agent交接/规划。GUI、训练、tensor/GPU不进默认标准库。

停止条件：无网络离线闭环、坏工具参数、有限预算终止、取消/资源释放、版本化检查点恢复和重复副作用策略可复现。真实模型是可选集成验收，不作为基础回归外部依赖。

### S7：按实际需求补长尾

CSV/TOML、Unicode/regexp/fmt、日期时区、压缩归档、HTTP服务端、完整FFI、网络注册中心/包生态长尾、benchmark分别小步定范围；本地包清单/锁/来源与源码分发底座提前独立切片，见 [新规划配套](#next-generation-ecosystem-plan)。复杂解析/密码/压缩优先成熟依赖；矩阵/FFT/优化求解放可选包，SIMD/并行归约另定精度与可移植性。

| 图与工作流 | BFS/DFS、拓扑排序/环检测、Dijkstra；A* 后续 | 可手写；无公共图算法 | 容器完成后做 Hua 源码库 |
| 字符串算法 | 统一索引语义的搜索、编辑距离、差异比较、规范化 | 有简单子串/字节偏移搜索 | 按实际文本任务扩展 |
| 检索评分 | dot/norm/cosine、top-k、稀疏词频、BM25 | SIMD 只有逐元素加减乘 | 先基础向量与 top-k，后检索包 |
| 矩阵与数值计算 | Matrix、矩阵乘、分解、FFT、优化求解 | 无矩阵/张量系统 | 可选数值包或 Native/Python |
| 并行算法 | parallel reduce、确定性聚合、批处理 | 有受限 parallel map；无通用归约 | 冻结数值与取消规则后 |

对照依据：Go [slices](https://pkg.go.dev/slices) 提供排序/二分/反转等；Python [heapq](https://docs.python.org/3/library/heapq.html) 提供堆与优先选择；Rust [collections](https://doc.rust-lang.org/std/collections/index.html) 提供集合、双端队列和堆；Python [itertools](https://docs.python.org/3/library/itertools.html) 提供序列组合工具，[statistics](https://docs.python.org/3/library/statistics.html) 提供统计，[graphlib](https://docs.python.org/3/library/graphlib.html) 提供拓扑排序。Dijkstra/A*、BM25、矩阵和 FFT 是 Hua 的扩展建议，不能据此声称这些语言都在标准库包含它们。

优先队列可复用于 top-k、最短路径和任务优先级；Deque 可复用于 BFS 与事件队列。先做这些通用结构，比逐项内建每个图算法更有收益。
可复现随机与安全随机分开：前者用于实验和采样，后者用于凭证或不可预测标识。参照 [Python random](https://docs.python.org/3/library/random.html) 与 [secrets](https://docs.python.org/3/library/secrets.html)。

### Agent 方向的具体清单

一个可独立部署的 Agent，至少要完成“读配置 → 发起模型请求 → 接收输出/工具请求 → 校验参数 → 调用工具 → 保存状态与日志 → 下一轮/结束”。当前 Hua 可以编写本地控制流程和 JSON 处理，但缺少组成该闭环的原生通信与状态管理接口。

| 能力 | 已有基础 | 缺口与建议 | 依赖/顺序 |
|---|---|---|---|
| 配置与凭证输入 | args、文件/JSON、getenv | 参数解析；凭证值不进入默认日志 | getenv已完成；随后配置封装 |
| 请求时间与预算 | Task 超时/取消、两种时钟 | 请求截止时间、轮数/工具次数/令牌与费用预算 | 时钟已完成；预算放 Agent 包 |
| 模型通信 | JSON、Bytes | HTTP/HTTPS、headers、JSON 请求、状态码、连接/读取超时 | S4 |
| 流式输出 | stdin/read_line | 增量响应、UTF-8 分片解码、SSE 解析、关闭/取消/背压 | I/O 流和 HTTP 完成后 |
| 结构化参数 | Json getter、Result | 构造/更新 Json、Schema 子集校验、字段路径错误 | S1 JSON；后续 schema 包 |
| 工具注册与调用 | fn/struct/interface、模块 | 名称/描述/参数 schema、结果封装、工具调用 ID、错误分类 | Agent 包；工具表可先显式注册 |
| 外部工具 | Native/WASM/Python 前台调用 | subprocess 参数数组、stdio 管道、超时、退出码与输出上限 | 资源句柄和流完成后 |
| 协议互通 | 无原生协议库 | JSON-RPC、MCP 客户端/服务器、stdio 与 Streamable HTTP | 网络/进程/Schema 后，独立包 |
| 会话与恢复 | 文本/JSON 文件、同卷replace | JSONL、持久flush、SQLite、版本化检查点、工具副作用记录 | S1文件；S5数据库 |
| 可靠调用 | Result、Task | 错误分类、指数退避/抖动、限流、幂等键、重试预算 | 时钟/随机/HTTP 上的源码库 |
| 并发调度 | taskgroup、all/race | 任意规模的有界任务队列、取消传播、输出流、可中断 I/O | 保留线程上限；扩展任务合同 |
| 调试与评测 | print、外部测试 | 结构日志、trace/span、工具耗时、离线模型替身、录制/重放 | S1日志；Agent 评测包 |
| 检索与记忆 | Map/文件 | 文本切分、去重、BM25、embedding 接口、向量索引/存储 | 算法库 + 网络/存储扩展 |
| 工具能力边界 | 现有 mut 与任务限制 | 工作目录/网络/命令范围、执行预算、按工具声明的操作策略 | 工具层与宿主协同设计 |

Go [net/http](https://pkg.go.dev/net/http) 与 [context](https://pkg.go.dev/context) 可参考请求和取消的组合；Python [time](https://docs.python.org/3/library/time.html) 区分单调时钟与现实时间。
MCP 的通信与工具数据模型参考 [传输规范](https://modelcontextprotocol.io/specification/latest/basic/transports) 和 [工具规范](https://modelcontextprotocol.io/specification/latest/server/tools)；schema 参考 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)。实现时须固定支持的协议版本和 Schema 范围，并用对照测试验证；“能解析 JSON”不等于兼容 MCP 或完整 JSON Schema。

write_text直接截断写。S1a可用temp_file写入后replace完成同卷发布；完整恢复还需要失败/清理处理、持久flush和工具幂等策略。取消一个 Task 也不能停止当前被禁止放入后台的 Python/Native 调用，更不保证任意阻塞 I/O 可被中断。

## 网络、错误与轻量发行的后续安排

本节对应 [后置方向](设计决策与未决事项.md#deferred-directions)，不新增可调用接口。ER1与File/CPU Task恢复已经交付；S1b纳入B07，其余错误便利性、N网络和D发行扩展按当前优先级另选。下面是库族依赖，不是当前默认实施顺序。

### 标准责任与按需依赖

std.*保证公共API/语义/维护责任；不意味着所有标准后端都必须进最小Core。HTTP/URL等标准方向独立于Python，网络/TLS依赖可随标准发行配置提供、在纯计算Core中按能力清单省略。缺模块/后端必须执行前报告，不能运行后换后端重跑。

复杂协议/密码使用成熟组件，不自研TLS/QUIC；库版本、支持协议、许可、信任根分发与目标平台在实现任务冻结。高层Web/Agent/RPC/数据库仍可选包。原生后端、Python兼容包和Hua源码库是不同分发边界；不为多个别名维护相同标准接口。

### 各库族的交付边界与依赖

| 次序 | 具体小交付 | 必须单独验收 |
|---|---|---|
| S1b＋ER0 | Json构造/持久更新/JSONL与配置；接口级错误形状/缺失/容量/部分副作用盘点 | 本地配置读改写；旧string Err仍有效，配置格式错误不能默认回退成空配置。 |

### S4客户端实施前的合同表

| 维度 | 建议冻结方向／尚需细化 |

### Typed Transport、可靠Agent与优化的落点

typed消息先确定独立wire schema：字段ID/名字、版本/缺失默认、整数宽度与端序、浮点有限性、UTF-8、未知字段和总大小限制。JSON、二进制等各有编码合同，不能直接发送本机struct布局/GC指针。先显式编码/解码函数，再评估属性/生成工具；候选@message不增加当前属性集合。Typed RPC不依赖QUIC，生成Schema也不代表可安全访问网络。

Agent首版可靠性来自明确工具表/输入校验、Result错误、资源结束、deadline/有界并发与状态发布。all_settled、重试退避/限流等是组合库候选；领域错误、操作已提交状态和幂等键须保存，取消不等于交易回滚，业务检查点不保存活跃Task栈或socket。先离线替身与可控HTTP服务，真实模型后接。

N5池/多段I/O先验证owner/租约和实际复制成本，再专用后端；N6协议组件/QUIC按需求，N7调度只在上界内、可解释且可关闭。网络→CPU/GPU→流式输出共享取消/预算不等于把每个请求自动交给GPU。服务器、低延迟游戏和音视频分别有可靠性与负载合同，不以单个吞吐榜单决定所有默认。
