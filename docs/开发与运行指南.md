```powershell

.\scripts\build.ps1
```

## 1. 保存程序

在 VS Code 中打开你的程序文件夹，新建并保存 main.hua（扩展名必须是.hua）。例如：

```hua
fn main() {
    print("Hello Hua")
}
```

## 2. 在终端运行

点击 VS Code 菜单“终端 → 新建终端”。确认终端的当前目录就是main.hua所在文件夹，然后输入：

```powershell
hua run .\main.hua
```

预期输出：

```text
Hello Hua
```

运行源码无需先手动build。修改程序后先保存，再运行同一命令。
如果提示文件不存在，切换到文件所在目录，或把main.hua换成完整路径。

## 3. 终端提示找不到 hua 时

本机项目位于C:/file/project/hua，可以直接使用已经构建好的核心，保持终端仍在你的程序文件夹：

```powershell
& "C:\file\project\hua\tests\build\hua.exe" run .\main.hua
```

&是PowerShell调用带引号路径的方式。其他电脑请替换为真实hua.exe路径，并保持wasmtime.dll在其旁边。
想以后直接输入hua，在Hua仓库目录执行一次安装配置：

```powershell
Set-Location C:\file\project\hua
.\scripts\install-local.ps1 -AddToUserPath
```

随后重新启动VS Code，再打开你的程序文件夹和新终端，运行hua run。详细安装见 [开发环境指南](开发与运行指南.md)。
插件设置hua.compilerPath只影响插件命令，不会自动让终端识别hua；终端仍需PATH或上面的完整路径。

## 4. 使用 VS Code 插件运行

保存并保持main.hua为当前编辑文件，按Ctrl+Shift+P，搜索并选择：

```text
Hua: Run Current File
```

程序输出显示在下面的任务终端，可在终端输入stdin。插件以打开的项目文件夹作为工作目录；没有打开文件夹时使用当前文件目录。
也可选择Hua: Check Current File只检查，Hua: Build Current File生成同名.huab。
如果没有这些命令，先安装Hua插件，在Hua仓库目录执行：

```powershell
code --install-extension .\tests\build\hua-language-0.1.0.vsix
```

然后重新打开.hua文件，确认右下角语言模式为Hua。插件运行要求项目可信；未配置PATH时，在VS Code设置hua.compilerPath为真实hua.exe绝对路径。

## 5. 需要参数或保存字节码时

```powershell
hua run .\main.hua -- first second
hua check .\main.hua
hua build .\main.hua -o .\main.huab
hua run .\main.huab
```

--后为程序参数，通过std.os.args()读取。build是可选的字节码保存步骤，生成的.huab仍用hua run执行。


需要测试运行时间或拆分模块时，见 [运行计时与模块结构](开发与运行指南.md)。

## Windows安装、VS Code与自举

### Windows 安装与环境变量

项目根目录执行（先按下文构建tests/build）：

```powershell
.\scripts\install-local.ps1 -AddToUserPath
hua version
hua run .\examples\hello.hua
hua check .\examples\concurrency.hua
hua build .\examples\concurrency.hua -o .\tests\build\concurrency.huab
hua run .\tests\build\concurrency.huab
```

默认从tests/build复制hua.exe、wasmtime.dll、Wasmtime许可与Hua许可到 LOCALAPPDATA/Hua/bin。可用-BuildDirectory指定其他构建、-Destination指定安装bin路径；路径允许中文和空格。
脚本会让当前PowerShell会话立即可用。显式-AddToUserPath追加用户PATH并设置HUA_HOME；其他终端和VS Code需要重新打开。没有管理员/系统PATH修改，不改变PowerShell执行策略。
HUA_HOME只是安装位置约定，当前模块加载器不读取它。当前没有HUA_PATH全局包搜索；源码import按既有相对模块规则，标准库是内建模块。程序工作目录仍是启动时目录，文件相对路径按此解析。
Python Bridge为可选独立插件；核心安装不复制CPython/Python包或Native/WASM扩展。使用这些扩展仍须部署模块及匹配外部依赖，HUAB不嵌入这些运行文件。
运行Hua程序不需要本机C++工具链；仅修改和构建现有C++核心时才需要C++20/CMake/Wasmtime SDK。

### 自举已从哪里开始

[selfhost/lexer.hua](../selfhost/lexer.hua)现在是Hua编写的词法器，入口为[selfhost/main.hua](../selfhost/main.hua)。它能扫描自己的源码；关键字和最长操作符采用Map查找，以适应既有100万执行步预算。
支持当前关键字/操作符、各进制数字/下划线/浮点指数、字符串转义、UTF-8字符串与注释、嵌套普通/文档块注释、BOM和换行规范化，并产生行号/UTF-8字节列。标识符沿用ASCII规则。
输入通过std.fs.read_text进行UTF-8校验；非法编码会在文件接口处报Err，未复现C++ Lexer的E1009原始字节诊断。其他已对照的词法错误输出error E编码@行:列，不提供完整源码下划线。旧词法CLI原型遇错打印结果并正常结束；C01新增开发命令已约定非零失败退出，见下方Parser入口，公共main规则未变。

```powershell
hua run .\selfhost\main.hua -- .\examples\hello.hua
hua run .\selfhost\main.hua -- .\selfhost\lexer.hua
hua build .\selfhost\main.hua -o .\tests\build\hua-lexer.huab
hua run .\tests\build\hua-lexer.huab -- .\examples\hello.hua
```

上面只是最早的词法器入口。**2026-10-22起，完整Hua编译器 `selfhost/archive_main.hua` 已能编译自身，并到达代际不动点**（第二、第三代HUAB逐字节相同）。本机Windows复现（约8分钟一次，计时期间避免其他重负载）：

```powershell
New-Item -ItemType Directory -Force .\tests\build-selfhost | Out-Null
# 1. 宿主C++前端构建第一代编译器（约40秒）
.\tests\build\hua.exe build .\selfhost\archive_main.hua -o .\tests\build-selfhost\compiler.huab
# 2. 第一代编译器编译自身源码，得到第二代
.\tests\build\hua.exe run .\tests\build-selfhost\compiler.huab --execution-profile compiler --report-budget -- .\selfhost\archive_main.hua .\tests\build-selfhost\gen2.huab
# 3. 第二代再编译自身，得到第三代；gen2与gen3应逐字节相同
.\tests\build\hua.exe run .\tests\build-selfhost\gen2.huab --execution-profile compiler --report-budget -- .\selfhost\archive_main.hua .\tests\build-selfhost\gen3.huab
```

成功时stdout是 `"status":"ok"` 的 hua.archive.result.v1 回执，stderr是步数与调用深度。当前耗时、步数与产物身份只以[项目概览：自举](项目概览与进度.md#current-bootstrap-evidence)为准。

|---|---|---|
| Stage0：现有宿主 | C++编译器+VM，Hua词法器 | 已有词法器源码/VM/无源码HUAB对照与扫描自身源码 |

## 语言入门与已有示例

### 4. 写第一个 Hua 程序

[examples/quickstart.hua](../examples/quickstart.hua) 的完整内容是：

```hua
# Hua 入门：函数、循环、变量和除法
fn add(a int, b int) int {
    return a + b
}

fn main() {
    var total = 0
    for i in 0..5 {
        total += i
    }
    print("Hua", add(20, 22))
    print(total)
    print(7 / 2, 7 // 2, 7 % 2)
}
```

`0..5` 包含 0、不包含 5；因此 total 为 10。
`fn main()` 是可选的零参数入口，执行器先完成模块与顶层初始化，再自动调用它。
`let` 不可重新绑定，`var` 可修改，`const` 当前仅做支持范围内的编译期标量计算。
声明目前必须初始化。函数参数和返回值可写类型注解；普通 int/float 混算需要显式转换。

运算与注释要点：

| 写法 | 含义 |
|---|---|
| `7 / 2` | 3.5，真除法 |
| `7 // 2` | 3，int 整除；`-5 // 2` 为 -3 |
| `7 % 2` | 1；负数余数与整除共同满足对应公式 |
| `2 ** 3` | 8，幂；幂右结合 |
| `# 注释` | 单行注释 |
| `#* 内容 *#` | 可嵌套块注释 |
| `##` / `#** ... **#` | 文档标记预留，当前按注释跳过 |

`//` 始终是整除，`/* ... */` 不是注释。文件首行 `#!` 可用作 shebang。
更多例子见 [fibonacci](../examples/fibonacci.hua)、[struct](../examples/struct.hua)、[binary_search](../examples/binary_search.hua)、[comments](../examples/comments.hua)。

#### Map、多个结果与可恢复错误

完整可运行代码见 [values.hua](../examples/values.hua)，逐项冻结规则见 [值与结果规则](语言设计与类型规则.md)。

```powershell
.\tests\build\hua.exe run .\examples\values.hua
.\tests\build\hua.exe interpret .\examples\values.hua
.\tests\build\hua.exe build .\examples\values.hua -o .\tests\build\values.huab
.\tests\build\hua.exe run .\tests\build\values.huab
```

三种运行方式均输出：

```text
2 true nil
11
1 3
ok(5) err(division by zero)
true 4 true
```

Map 缺失键为 nil；先用局部 let 绑定，再 `!=nil` 检查或 unwrap。`has` 可区分值为 nil 和不存在。
`let/var a,b=f()` 接收多个结果，`a,b=b,a` 交换；`_` 丢弃。全部 RHS 计算/检查完成后才写入目标。
Result<T> 默认为字符串错误；`?` 在返回 Result 的函数中提前传播 Err。unwrap_or 的默认参数总会立即求值。
Map/Result 解包后的只读能力不能通过 var 别名提升；需要独立修改时 clone。函数结果写能力暂不跨函数推断。
Optional<Result> 和 Map 的直接 Result 值暂不支持；完整控制流收窄、通用 Tuple 和容器结构比较仍待设计。

#### 从输入和文件处理 JSON

```powershell
'hello' | .\tests\build\hua.exe run .\examples\standard_library.hua -- .\examples\data\profile.json
'hello' | .\tests\build\hua.exe interpret .\examples\standard_library.hua -- .\examples\data\profile.json
.\tests\build\hua.exe build .\examples\standard_library.hua -o .\tests\build\standard_library.huab
'hello' | .\tests\build\hua.exe run .\tests\build\standard_library.huab -- .\examples\data\profile.json
```

输出 `HUA:3:hello`；[完整示例](../examples/standard_library.hua) 使用 os.args 获取路径、fs.read_text 读取文件、json.decode/get/as_* 获取数据，
再由 io.read_line 读取一行和 strings.upper_ascii 转换名字。数据路径相对启动工作目录，源码导入规则仍相对入口目录。
stdin 的 EOF 是 Ok(nil)，空行是 Ok("")；JSON null 使用 json.is_null 检测。
输入/文件/JSON 的可恢复错误统一为 Result；纯字符串函数返回常规值，资源超限可报 E4099。
37 个函数的签名和冻结边界见 [基础标准接口](标准库与内建接口.md)。

| 校验 HUAB | `.\tests\artifacts\build\hua.exe check .\tests\artifacts\build\quickstart.huab` |
| 运行 HUAB | `.\tests\build\hua.exe run .\tests\build\quickstart.huab` |

`build file.hua` 默认输出同名 `.huab`，也可以用 `-o` 指定路径；输出扩展名须为 `.huab`。
`bytecode` 也接受 HUAB；`ast`、`interpret`、`build` 不接受 HUAB 输入。
check/build 不执行程序初始化。check 源码会检查依赖图；check HUAB 校验文件与指令，不重新证明完整源码语义。
退出码：0 成功，1 输入/读取/检查/执行或普通入口Err，2 命令用法错误，3 内部故障；程序调用`std.os.exit(n)`（0..125，2026-10-24）时为`n`，此时由程序决定含义。Result入口与分类规则见 [A06公开入口](#a06-public-entry)。
当前没有交互 REPL；run/interpret 使用 `--` 传递程序参数，`.huab` run 同样支持。

## 计时、应用模块与编译器目录

### 当前有什么时间接口

std.task.sleep(ms)让当前任务/线程等待，std.task.timeout(t,ms)等待任务并处理超时。二者不能读取当前时间或某段代码耗时。
已提供std.time.monotonic_ns()用于进程内耗时、std.time.unix_ms()用于现实时间戳；没有Stopwatch/日期格式/时区接口。合同见 [第十二阶段](标准库与内建接口.md)。

```hua
import std.time as time
import std.task as task
fn main() {
    let begin = time.monotonic_ns()
    task.sleep(12)
    let elapsed = time.monotonic_ns() - begin
    print("elapsed_ns", elapsed)
    print("elapsed_ms", float(elapsed) / 1000000.0)
}
```

elapsed为本次代码段耗时，单调时钟单位是纳秒，不代表精度为纳秒。将等待替换为要测试的函数。

### 在 VS Code 终端测整个程序

保存main.hua，在文件所在目录打开PowerShell终端。已经配置PATH时：

```powershell
$taskElapsed = Measure-Command { hua run .\main.hua | Out-Host }
$taskElapsed.TotalMilliseconds
```

前面显示程序输出，最后的数字是本次整体耗时（毫秒）。如终端找不到hua，本机可以直接用完整路径：

```powershell
$taskElapsed = Measure-Command {
    & "C:\file\project\hua\tests\build\hua.exe" run .\main.hua | Out-Host
}
$taskElapsed.TotalMilliseconds
```

Measure-Command返回TimeSpan；TotalMilliseconds是完整毫秒数，包括不足1毫秒的小数，不能用Milliseconds分量代替。参见 [PowerShell官方说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/measure-command)。
源码运行的整体计时包含进程启动、读取/检查/编译、VM运行、输出和退出清理，含等待任务/外部I/O；它不是某个函数的纯执行耗时。失败的程序同样会得到耗时，检查终端诊断与$LASTEXITCODE，失败结果不能作为正常运行比较。

### 少计入源码编译开销

先生成HUAB，再单独测字节码运行：

```powershell
hua build .\main.hua -o .\main.huab
$taskElapsed = Measure-Command { hua run .\main.huab | Out-Host }
$taskElapsed.TotalMilliseconds
```

仍包含进程启动、HUAB读取/验证、VM运行、输出和清理。比较性能时使用相同输入，多次测量；大量print和等待输入会影响结果。只看计算时可把循环内输出移到最后，或将Out-Host换为Out-Null（仍包含程序内部生成输出的开销）。
在Hua代码内测函数/代码段可使用上面的monotonic_ns；终端计时仍适合检查整个进程。

### 你的 Hua 应用如何拆成模块

最小结构：

```text
我的项目/
  main.hua
  mathops.hua
```

main.hua：

```hua
import mathops as math
fn main() {
    print(math.add(3, 4))
}
```

mathops.hua：

```hua
pub fn add(a int, b int) int {
    return a + b
}
```

在“我的项目”目录运行：

```powershell
hua run .\main.hua
```

输出7。跨模块调用需要pub。也可把mathops.hua换为mathops/package.hua，main.hua的import不变；package.hua是目录模块入口，不会自动扫描/合并目录里所有源码文件。
所有本地模块的解析根固定为入口源码main.hua所在目录，嵌套模块的import也以此根解析。import a.b依次寻找a/b.hua、a/b/package.hua，然后才是已支持Native/WASM文件。不要把入口放进src后还假设能导入其父目录下的模块。
项目源码导入与程序读写文件不同：模块根是入口源码目录，std.fs相对文件路径则按启动工作目录解析。安装Hua和HUA_HOME不会自动加入全局源码模块目录；目前没有HUA_PATH或远程包管理。

```powershell

```

输出5，然后4 6。源码模块与依赖链接后可build为单个HUAB；Native/WASM等外部文件仍须另行部署。

## A06：入口失败与公开Hua编译器

最简单的`fn main(){print("Hello, Hua")}`无需声明返回类型或return；正常结束退出0。显式Result入口推荐`fn main() Result<void>`，返回ok()成功，返回Err或?传播失败会在所有清理完成后向stderr报告，退出非零。详细语义只维护 [入口合同](语言设计与类型规则.md#a06-entry-contract)。可运行 [入口示例](../examples/entry_result.hua)：

```powershell
.\tests\build\hua.exe run .\examples\entry_result.hua
$LASTEXITCODE # 0，stdout为Hello, Hua
.\tests\build\hua.exe run .\examples\entry_result.hua -- unexpected
$LASTEXITCODE # 1，stderr为入口Err
```

| 公开CLI结果 | 退出码/报告 |
|---|---|
| help/version/check/tests/artifacts/build/运行正常完成 | 0；成功结果在stdout，失败消息不会伪装OK/Built |
| 输入读取、语法/类型、损坏HUAB、执行诊断、预期输出写入失败 | 1；stderr保留既有诊断码与可用来源，文件I/O用E0001 |
| 命令参数错误、无效输出扩展名/输入命令组合 | 2；stderr E0004与Usage；输出参数先验证，不加载输入 |
| 意外宿主异常/内部不变量 | 3；stderr E0002；VM/编译器内部E6001保留原码并退出3 |
| main自动入口返回Err | stderr E0003及main定义位置；string/普通Error默认1，Error根hua.cli.usage为2、hua.cli.internal为3 |

程序此前已输出的stdout仍保留，不承诺失败时stdout一定为空。没有通过?自动捕获Diagnostic；int返回值仍不映射为退出码。结构化错误示例为`return err(unwrap(e.make("hua.cli","usage","expected input.hua")))`，需导入`std.error as e`并声明`Result<void,e.Value>`。

[selfhost/compiler_main.hua](../selfhost/compiler_main.hua)是新增公开Hua编译器入口，复用已有types/bytecode/archive模块。当前命令为help和build，要求显式-o；输入覆盖仍是当前C04-T1/C06/C07子集。生产hua.exe build继续使用C++前端。

```powershell
.\tests\build\hua.exe run .\selfhost\compiler_main.hua -- --help
.\tests\build\hua.exe run .\selfhost\compiler_main.hua --execution-profile compiler -- build .\examples\hello.hua -o .\tests\build\public-hello.huab
$LASTEXITCODE # 0
.\tests\build\hua.exe check .\tests\build\public-hello.huab
.\tests\build\hua.exe run .\tests\build\public-hello.huab
```

成功输出`Built <output>`；用法错误2，读取/语法/类型/预算/写入错误1，明确E8203内部不变量映射3；stderr包含原阶段E编码/位置与compiler stage。Hua生成并验证指令、编码HUAB、同目录临时写后替换，失败保留既有输出并清理临时文件，不执行待编译程序。直接入口沿用archive.publish，不承诺断电持久性或新增运行时独立读取器；需要独立reader/fsync及JSON小回执时仍使用tools/hua_frontend.py build的现有开发协议。

可先用宿主构建此入口组件：

```powershell

.\tests\build\hua.exe run .\tests\build\hua-compiler.huab --execution-profile compiler -- build .\examples\hello.hua -o .\tests\build\public-hello.huab
```

组件HUAB由C++宿主构建；组件运行时用Hua编译输入，不代表完整自身编码或C08代际已经通过。旧parser/archive等JSON入口保持其void main及旧协议，不能把stdout中的error自动猜成入口Err；CI可继续使用Python开发命令。
