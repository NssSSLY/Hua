# 标准库差距与算法及智能体路线

2026-10-06。根据当前源码与 Python、Go、Rust 官方文档整理。本文用于确定补齐范围和顺序，第一批25接口已实现并冻结，见 [第十二阶段](第十二阶段_数学算法时钟与配置.md)；其余新增模块名、接口名与合同均为建议，尚未实现或冻结；可调用清单仍以 [内建标准库目录](内建标准库目录.md) 和 [内建方法目录](内建方法目录.md) 为准。

Hua 已有文件、字符串、JSON、字节、动态列表和任务的基础能力。算法方向主要缺可复用的序列算法、数据结构和数值工具；Agent（智能体）方向主要缺对外通信、可组合的超时与流、工具协议和可恢复状态。两条路线应共享基础设施，避免把每一个高层功能都做成运行时内建函数。

## 当前基线

| 已有能力 | 当前范围 | 不应误认为已支持 |
|---|---|---|
| 14 个标准模块、115 个函数 | os 3、io 3、fs 10、strings 13、json 12、bytes 13、buffer 10、list 10、gc 4、task 9、simd 4、math 12、alg 10、time 2 | 完整系统库、算法库或 Agent SDK |
| 38 个公开全局函数 | 基础输出/转换、len/clone、sqrt/min/max/abs/clamp、Map 和 Result/Optional 操作等 | 无需import的集合排序、统计、随机数；标准排序现在通过std.alg |
| 数组/Slice、Map、List<T> | 数组索引与视图；Map 键限 bool/int/string，已有遍历；List 用 snapshot 遍历 | 任意键哈希容器、Set、Deque、Heap、惰性迭代器 |
| 泛型、结构、闭包、enum/interface | 当前显式单态化和已验收子集 | 完整泛型约束、所有形式的回调和可变捕获 |
| async/taskgroup/parallel/SIMD | 有界线程、私有快照、协作取消；浮点数组 SIMD 加减乘 | 异步 I/O 事件循环、Channel、矩阵或通用并行归约 |
| Python Bridge | 可选 13 个 wrapper 接口，导入/调用/句柄与 JSON 转换 | 纯 Hua 实现、后台 Python 调用、自动转译、零复制或隔离执行 |

注册表：[stdlib.cpp](../src/stdlib.cpp)；全局函数：[runtime.cpp](../src/runtime.cpp)；类型特化：[binary_stdlib.cpp](../src/binary_stdlib.cpp)。现有 [二分查找示例](../examples/binary_search.hua) 是用户函数，不是内建标准算法。Map 当前底层使用有序 std::map，不能把它标作 HashMap；已有快照遍历也不能列为完全缺失。

## 成熟语言的比较

标准库的规模和边界因语言而异；目标应是覆盖 Hua 的实际用途，不以模块或函数数量作为完成百分比。

| 对照 | 算法与基础库代表 | 对 Agent 有帮助的基础 | Hua 可参考的设计 |
|---|---|---|---|
| Python | collections、heapq、bisect、itertools、functools、math、statistics、random、graphlib | urllib/http、ssl、asyncio、subprocess、sqlite3、logging、json、time | 面向日常任务的便捷组合和数据处理 |
| Go | slices/sort、container/heap、math、math/rand、maps | net/http、context、time、io/bufio、os/exec、encoding/json、log/slog、database/sql | 明确资源生命周期、取消传播、流式 I/O |
| Rust | Vec/VecDeque、HashMap/HashSet、BTreeMap/BTreeSet、BinaryHeap、slice 算法、Iterator | std::io/fs/net/process/time/thread/sync | 容器和算法的类型、所有权与资源边界 |

模块归属依据：[Python 标准库](https://docs.python.org/3/library/)、[Go 标准库](https://pkg.go.dev/std)、[Rust std](https://doc.rust-lang.org/std/)。Go 的 [database/sql](https://pkg.go.dev/database/sql) 提供通用接口，具体数据库驱动另行接入；Rust 的通用 HTTP 客户端、JSON 及异步运行时通常由生态包提供。Rust std 页面将 random 标为实验性，稳定随机工具仍通常选生态包；比较时区分稳定标准接口与实验功能。

Agent 编排框架也属于生态层。例如 [OpenAI Agents SDK](https://github.com/openai/openai-agents-python) 是单独安装的包。以下对 Hua 的分层和优先级，是结合当前实现作出的工程建议。

## 算法方向的具体清单

| 算法组 | 建议能力 | 当前情况 | 顺序 |
|---|---|---|---|
| 排序与查找 | sorted、stable_sort、sort_by、contains/index、lower_bound/upper_bound/binary_search | 已有自然顺序排序/查找；无比较器 | 第一批完成，第二批比较器 |
| 序列变换 | reverse、unique、chunk、zip、enumerate、filter/map/fold/scan | 有数组遍历与 List；无通用管线 | 第二批；惰性版本另设计 |
| 数据结构 | Set、Deque、Heap、PriorityQueue、Counter、LRU | Map/List 可手工模拟一部分；无公共封装 | 第二批先队列/堆/集合 |
| 数学基础 | 舍入、三角、对数、指数、gcd/lcm、位计数 | 已有12个默认float标准函数 | 第一批完成，第二批整数 |
| 统计与采样 | sum、mean、median、variance/stddev、quantile、seed、shuffle/sample | 已有sum，统计/采样待补 | 第二批 |
| 图与工作流 | BFS/DFS、拓扑排序/环检测、Dijkstra；A* 后续 | 可手写；无公共图算法 | 容器完成后做 Hua 源码库 |
| 字符串算法 | 统一索引语义的搜索、编辑距离、差异比较、规范化 | 有简单子串/字节偏移搜索 | 按实际文本任务扩展 |
| 检索评分 | dot/norm/cosine、top-k、稀疏词频、BM25 | SIMD 只有逐元素加减乘 | 先基础向量与 top-k，后检索包 |
| 矩阵与数值计算 | Matrix、矩阵乘、分解、FFT、优化求解 | 无矩阵/张量系统 | 可选数值包或 Native/Python |
| 并行算法 | parallel reduce、确定性聚合、批处理 | 有受限 parallel map；无通用归约 | 冻结数值与取消规则后 |

对照依据：Go [slices](https://pkg.go.dev/slices) 提供排序/二分/反转等；Python [heapq](https://docs.python.org/3/library/heapq.html) 提供堆与优先选择；Rust [collections](https://doc.rust-lang.org/std/collections/index.html) 提供集合、双端队列和堆；Python [itertools](https://docs.python.org/3/library/itertools.html) 提供序列组合工具，[statistics](https://docs.python.org/3/library/statistics.html) 提供统计，[graphlib](https://docs.python.org/3/library/graphlib.html) 提供拓扑排序。Dijkstra/A*、BM25、矩阵和 FFT 是 Hua 的扩展建议，不能据此声称这些语言都在标准库包含它们。

优先队列可复用于 top-k、最短路径和任务优先级；Deque 可复用于 BFS 与事件队列。先做这些通用结构，比逐项内建每个图算法更有收益。
可复现随机与安全随机分开：前者用于实验和采样，后者用于凭证或不可预测标识。参照 [Python random](https://docs.python.org/3/library/random.html) 与 [secrets](https://docs.python.org/3/library/secrets.html)。

## Agent 方向的具体清单

一个可独立部署的 Agent，至少要完成“读配置 → 发起模型请求 → 接收输出/工具请求 → 校验参数 → 调用工具 → 保存状态与日志 → 下一轮/结束”。当前 Hua 可以编写本地控制流程和 JSON 处理，但缺少组成该闭环的原生通信与状态管理接口。

| 能力 | 已有基础 | 缺口与建议 | 依赖/顺序 |
|---|---|---|---|
| 配置与凭证输入 | args、文件/JSON、getenv | 参数解析；凭证值不进入默认日志 | getenv已完成；随后配置封装 |
| 请求时间与预算 | Task 超时/取消、两种时钟 | 请求截止时间、轮数/工具次数/令牌与费用预算 | 时钟已完成；预算放 Agent 包 |
| 模型通信 | JSON、Bytes | HTTP/HTTPS、headers、JSON 请求、状态码、连接/读取超时 | 基础库第三批 |
| 流式输出 | stdin/read_line | 增量响应、UTF-8 分片解码、SSE 解析、关闭/取消/背压 | I/O 流和 HTTP 完成后 |
| 结构化参数 | Json getter、Result | 构造/更新 Json、Schema 子集校验、字段路径错误 | 第二批 JSON；后续 schema 包 |
| 工具注册与调用 | fn/struct/interface、模块 | 名称/描述/参数 schema、结果封装、工具调用 ID、错误分类 | Agent 包；工具表可先显式注册 |
| 外部工具 | Native/WASM/Python 前台调用 | subprocess 参数数组、stdio 管道、超时、退出码与输出上限 | 资源句柄和流完成后 |
| 协议互通 | 无原生协议库 | JSON-RPC、MCP 客户端/服务器、stdio 与 Streamable HTTP | 网络/进程/Schema 后，独立包 |
| 会话与恢复 | 文本/JSON 文件 | JSONL、原子替换、SQLite、版本化检查点、工具副作用记录 | 第二批文件；第三批数据库 |
| 可靠调用 | Result、Task | 错误分类、指数退避/抖动、限流、幂等键、重试预算 | 时钟/随机/HTTP 上的源码库 |
| 并发调度 | taskgroup、all/race | 任意规模的有界任务队列、取消传播、输出流、可中断 I/O | 保留线程上限；扩展任务合同 |
| 调试与评测 | print、外部测试 | 结构日志、trace/span、工具耗时、离线模型替身、录制/重放 | 第二批日志；Agent 评测包 |
| 检索与记忆 | Map/文件 | 文本切分、去重、BM25、embedding 接口、向量索引/存储 | 算法库 + 网络/存储扩展 |
| 工具能力边界 | 现有 mut 与任务限制 | 工作目录/网络/命令范围、执行预算、按工具声明的操作策略 | 工具层与宿主协同设计 |

Go [net/http](https://pkg.go.dev/net/http) 与 [context](https://pkg.go.dev/context) 可参考请求和取消的组合；Python [time](https://docs.python.org/3/library/time.html) 区分单调时钟与现实时间。
MCP 的通信与工具数据模型参考 [传输规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports) 和 [工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)；schema 参考 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)。实现时须固定支持的协议版本和 Schema 范围，并用对照测试验证；“能解析 JSON”不等于兼容 MCP 或完整 JSON Schema。

现有 write_text 是直接截断写，不能当作原子检查点；完整恢复还需要替换操作、失败处理和工具幂等策略。取消一个 Task 也不能停止当前被禁止放入后台的 Python/Native 调用，更不保证任意阻塞 I/O 可被中断。

## 建议如何组织库

| 层次 | 适合放入的能力 | 原因 |
|---|---|---|
| 运行时/宿主基础 | 时钟、环境、文件句柄、进程、网络、安全随机；现有值类型和 GC | 需要宿主资源、生命周期及执行器一致性 |
| 标准基础算法 | math、自然顺序序列算法、集合/队列/堆、统计、编码、路径、日志 | 高频、通用、可稳定验收；性能热点可用 Native 实现 |
| 随运行时分发的 Hua 源码库 | 图算法、重试/限流、工作流、纯数据组合 | 支持自举、避免将高层策略固化进 C++ 核心 |
| 可选生态包 | agent、llm、mcp、retrieval、数据库驱动、矩阵/张量、特定模型 SDK | 协议/服务变化快，依赖和部署需求各异 |

这些源码库需要补充安装和模块解析设计。当前 import 以入口源码目录为根，不能先写一个 std/*.hua 目录就宣称任意工程都能导入；可先作为工程普通模块验证，再设计内建/分发库搜索、版本和缓存。
Python Bridge 可用于早期试验现成包，但需要遵守句柄、数据复制和前台调用限制；涉及 async/回调的框架不应在未验证时宣称可直接导入运行。

## 分批补齐与验收

### 第一批：25 个接口已完成，通用算法与配置

| 已实现模块 | 接口 | 数量 |
|---|---|---:|
| std.math | floor、ceil、trunc、round、sin、cos、tan、exp、log、log2、log10、hypot | 12 |
| std.alg | sorted、reverse、contains、index、lower_bound、upper_bound、binary_search、sum、min、max | 10 |
| std.time | monotonic_ns、unix_ms | 2 |
| std.os 扩展 | getenv | 1 |

这些接口现在可导入调用；详细参数/返回/错误见 [第十二阶段](第十二阶段_数学算法时钟与配置.md)。带回调算法、泛型约束、事件循环、HTTP 和 Agent 框架仍待后续批次。

第一批规则概要：

- math 第一版显式接收/返回默认 float；不隐式混合所有精确数值。round已冻结为半值取偶数；log 的非正输入、溢出等以可识别错误返回，不生成 NaN/Infinity。后续精确类型须另定舍入合同。
- alg 第一版自然顺序支持 int/float/string 序列，sum 仅数值。sorted/reverse 返回新序列，不修改输入；别名和嵌套值写能力沿用现有容器规则。稳定排序、UTF-8 字节序、空集合 min/max 错误已冻结。
- 二分函数要求输入已按同一顺序排序；明确重复项取最左、未命中及插入位置。若要逐次检查有序性，须披露 O(n) 检查成本，不能同时承诺总操作 O(log n)。
- 整数 sum 检查溢出；浮点 sum 冻结顺序及误差边界，避免线程数改变结果。第一版不加不受控制的 parallel reduce。
- monotonic_ns 用于同一次进程的耗时/截止时间，纳秒单位不代表纳秒精度；unix_ms 用于现实时间，不能保证不回拨。跨进程和恢复状态不能保存单调时钟值作为时间戳。
- getenv返回Result<string?,string>，区分不存在、空字符串和失败；冻结变量名、Windows Unicode、编码错误及 Task 内环境读取的一致性。不默认记录变量值。

验收应覆盖解释器、VM、无源码 HUAB 三路径：排序/查找对独立参考实现，空/重复/越界/溢出/只读别名，时钟非递减及耗时，环境缺失/空值/中文。时间和错误路径不用单一精确数值断言；算法还须检查复杂度和操作预算。

### 第二批：容器、统计和 Agent 的本地基础

先做 Deque/Heap/Set、Map 便捷访问、List 插入删除、统计与可复现随机；同时补 path、文件元数据/原子替换/流、结构日志、Json 构造和 JSONL。
验收目标是本地候选排序/top-k、BFS/拓扑工作流、配置读取和可恢复会话文件。各模块独立冻结顺序、资源/别名、失败与容量规则，不把所有能力塞进一个大改动。

### 第三批：网络与数据库

建立资源句柄/close、取消与 Deadline 的统一入口，再完成 HTTP/HTTPS/URL、增量流/SSE、subprocess/管道和 SQLite。
网络测试使用本地服务与固定响应；数据库测试用临时数据库，不需要真实 API 密钥或付费模型。检验超时/取消、响应体上限、UTF-8 分片、TLS 验证、子进程清理与事务回滚。

### 第四批：最小 Agent 包

先用离线模型替身验收“消息 → 工具调用 → 校验 → 本地工具 → 保存 → 下一轮 → 结束”，再对接一个真实模型服务。
最小包包含消息/工具注册、有限轮次执行器、结构化输出校验、会话、取消/预算与 trace。多 Agent 交接、MCP、复杂记忆/RAG、自动规划随后扩展，逐一验收。

## 实现前必须处理的衔接点

- [stdlib.hpp](../include/hua/stdlib.hpp) 的 StandardFunction/RuntimeContext 与 [sema.cpp](../src/sema.cpp) 负责参数、动态签名和写能力；只新增运行时分支不能算完整接口。
- 当前 invoke_standard 没有统一的 Hua 函数回调入口。sort_by/filter/map/fold 若接收函数，需要解释器与 VM 的调用、异常、预算、取消和 GC 根接入；已有闭包并不自动完成该接口。
