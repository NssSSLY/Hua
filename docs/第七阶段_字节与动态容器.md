## 1. 使用与完整例子

在项目根执行：

```powershell
.\build\hua.exe check .\examples\binary_collections.hua
.\build\hua.exe run .\examples\binary_collections.hua -- .\build\bootstrap.bin
.\build\hua.exe interpret .\examples\binary_collections.hua -- .\build\bootstrap.bin
.\build\hua.exe build .\examples\binary_collections.hua -o .\build\binary_collections.huab
.\build\hua.exe check .\build\binary_collections.huab
.\build\hua.exe run .\build\binary_collections.huab -- .\build\bootstrap.bin
```

三种执行输出：

```text
[Hua, bootstrap] [Hua, bootstrap, ready]
17 4 255
-1 3741203396
```

[完整例子](../examples/binary_collections.hua) 增长列表、保留快照，用缓冲生成 17 字节的数据，再写入/读回二进制文件。
数据为 ASCII HUAB + 小端 u32(4) + byte(255) + 小端 i64(-1)。它是展示编码的普通二进制数据，不是可执行 HUAB 格式。
输入/输出路径相对启动工作目录，父目录不会自动创建；示例运行会创建/覆盖 bootstrap.bin。check/build 不执行这些操作。

## 2. 类型与能力

- `Bytes`：不可变的任意字节序列，允许 NUL、0x80–0xFF 和非法 UTF-8；赋值/clone 可共享不可变存储。
- `Buffer`：可追加的字节缓冲；复制句柄共享内容，clone 复制数据并获得独立写能力。
- `List<T>`：同质、可增长列表；复制句柄共享元素/长度，clone 深复制并获得独立写能力。T 可以是已支持的标量、Struct、容器或 Result 等类型，不能为 void。
- 三个名称在类型层保留，不能声明同名 struct。List<T> 为一个内建泛型，不代表用户自定义泛型已经开放；可使用 `List<int>`、`List<Token>` 注解。
- let、普通函数参数、只读字段/别名不允许 Buffer/List 修改；使用 var 和 `mut Buffer` / `mut List<T>` 参数。动态未知类型仍由运行时检查能力和元素类型。
- Buffer/List 构造器直接返回可写值；函数返回写能力仍保守，不做跨函数推断，需要独立修改时 clone。
- List 通过函数访问，不能直接 `xs[i]`、`xs[a:b]` 或 `for ... in xs`；遍历使用 list.snapshot。Buffer/Bytes 同样使用对应函数，核心 len 不扩展，使用模块 len。
- print/str 显示 `<Bytes:n>`、`<Buffer:n>`、`<List:n>`；不是内容编码。Json encode、Native/WASM 标量 ABI 不支持这三个值。

## 3. std.bytes（13 个）

```hua
import std.bytes as bytes
let raw=unwrap(bytes.from_ints([0,128,255]))
print(unwrap(bytes.to_ints(raw)),is_err(bytes.to_text(raw)))
let number=unwrap(bytes.u32_le(16909060))
print(unwrap(bytes.to_ints(number)),unwrap(bytes.read_u32_le(number,0)))
```

输出 `[0, 128, 255] true`，然后 `[4, 3, 2, 1] 16909060`。

| 函数 | 返回 | 合同 |
|---|---|---|
| from_ints(values []int) | Result<Bytes> | 各项须为 0..255，复制内容；空输入可用 |
| from_text(text string) | Bytes | UTF-8 验证后复制文本字节，保留 BOM/NUL/换行 |
| to_text(data Bytes) | Result<string> | 验证 UTF-8，失败 Err，不替换非法字符 |
| to_ints(data Bytes) | Result<[]int> | 各字节转 0..255 的只读 Slice |
| len(data Bytes) | int | 字节数 |
| at(data Bytes,index int) | Result<int> | 0..255 的单字节；负数/越界 Err |
| slice(data Bytes,start int,end int) | Result<Bytes> | 半开字节范围，复制内容，不要求 UTF-8 边界 |
| concat(a Bytes,b Bytes) | Result<Bytes> | 连接为新值，超限 Err |
| u32_le(value int) | Result<Bytes> | 0..4294967295，4 字节小端 |
| i64_le(value int) | Bytes | int64 二进制补码，8 字节小端 |
| read_u32_le(data Bytes,offset int) | Result<int> | 从字节偏移读取 4 字节，无对齐要求 |
| read_i64_le(data Bytes,offset int) | Result<int> | 从字节偏移读取 8 字节，无对齐要求 |
| crc32(data Bytes) | int | 与 HUAB/zlib 一致：CRC-32，反射多项式 0xedb88320，初值/最终 XOR 0xffffffff；结果 0..4294967295 |

crc32(empty)=0，crc32(ASCII "123456789")=3421780262。结果是校验值，不是签名。
Bytes 最多 128 MiB；from_ints/to_ints 最多 1,000,000 项；from_text/to_text 文本上限 16 MiB。
返回 Result 的操作把范围/UTF-8/资源失败放入 Err；from_text 资源超限 E4099、非法文本 E4003。

## 4. std.fs 二进制文件（新增 3 个）

| 函数 | 返回 | 合同 |
|---|---|---|
| read_bytes(path string) | Result<Bytes> | 读普通文件，允许任意字节，最多 128 MiB |
| write_bytes(path string,data Bytes) | Result<bool> | 创建/截断写入，成功 true |
| append_bytes(path string,data Bytes) | Result<bool> | 创建/追加写入，成功 true |

沿用 Phase 6 的 UTF-8 路径/拒绝路径 NUL、启动目录、进程权限、普通文件检查和错误规则。
不进行 UTF-8 内容验证或换行转换；目录、非普通文件、打开/读写/关闭错误为 Err。已有目标必须为普通文件，父目录不自动创建。
单次内容最多 128 MiB；累计 append 可超过该限制，此后 read_bytes 仍按文件总长检查。
写入不是事务/原子替换，失败可部分改变文件。没有文件句柄、seek、stream 或任意文件 offset 写入接口。
文本接口的 16 MiB/严格 UTF-8 合同不变。

## 5. std.buffer（10 个）

| 函数 | 返回 | 合同 |
|---|---|---|
| new() | Buffer | 新的空可写缓冲 |
| len(out Buffer) | int | 当前字节数 |
| append(out mut Buffer,data Bytes) | Result<int> | 追加原始字节，成功值为新总长度 |
| write_u8(out mut Buffer,value int) | Result<int> | 追加 0..255 的字节 |
| write_u32_le(out mut Buffer,value int) | Result<int> | 追加 0..4294967295 的 4 字节小端 |
| write_i64_le(out mut Buffer,value int) | Result<int> | 追加 int64 的 8 字节小端补码 |
| write_text(out mut Buffer,text string) | Result<int> | 验证 UTF-8 后追加文本字节 |
| bytes(out Buffer) | Bytes | 复制内容为不可变快照 |
| text(out Buffer) | Result<string> | UTF-8 验证后复制为文本 |
| clear(out mut Buffer) | void | 清空内容 |

最大 128 MiB，文本单次写入/导出最多 16 MiB。范围、UTF-8、大小检查在修改前完成；这些 Err 保持原内容和长度。
bytes 快照不受后续 append/clear 影响。实现允许保留已分配容量；不冻结增长倍数/容量，不提供借用底层指针。

## 6. std.list（10 个）

```hua
import std.list as list
var empty []int=[]
var values List<int> =list.from_slice(empty)
unwrap(list.append(values,1))
let old=list.snapshot(values)
unwrap(list.extend(values,[2,3]))
print(old,list.snapshot(values),unwrap(list.pop(values)))
```

输出 `[1] [1, 2, 3] 3`。类型的 `>` 与后面的 `=` 需分开，避免被识别成 `>=`。

| 函数 | 返回 | 合同 |
|---|---|---|
| from_slice(values []T) | List<T> | 从类型已确定的 Slice/数组深复制；不支持仅凭空 [] 推断 T |
| len(values List<T>) | int | 当前元素数 |
| get(values List<T>,index int) | Result<T> | 读取元素；负数/越界 Err；共享嵌套容器只读 |
| set(values mut List<T>,index int,value T) | Result<bool> | 替换现有元素，成功 true，不隐式增长 |
| append(values mut List<T>,value T) | Result<int> | 追加一项，成功值为新长度 |
| extend(values mut List<T>,items []T) | Result<int> | 追加 Slice/数组，成功值为新长度 |
| pop(values mut List<T>) | Result<T> | 取出并删除末项；空列表 Err，共享嵌套容器只读 |
| snapshot(values List<T>) | []T | 复制当前元素序列为只读 Slice |
| clear(values mut List<T>) | void | 清空元素 |
| reserve(values mut List<T>,capacity int) | Result<bool> | 预留容量，0..1,000,000；成功值是否发生扩容，不改变长度 |

T 一经构造不变，静态已知类型不匹配 E3004、动态不匹配 E4003；不隐式转换 append/set/extend 的 int 为 float。
最多 1,000,000 项；增长/容量/索引错误为 Err，失败不改变长度或元素。extend 先完成元素验证/复制再修改。
from_slice 深复制源容器；append/set/extend 沿用值复制：Struct 字段按值复制、Slice/Map/Buffer/List 句柄共享原有能力，不自动深复制。
get/pop 不开放嵌套共享容器写能力，需要修改时 clone。Struct 标量字段的独立值复制不作为共享引用。
snapshot 固定元素序列及 Struct 值，后续列表扩容/替换/删除不影响这个序列；它不深复制嵌套共享容器的内容，外部可写别名的修改仍可能被观察到。使用 clone 获得深层独立数据。
固定 Slice 不增加 append/resize 接口，旧视图/索引目标语义不变；列表也不开放可跨扩容持有的元素地址。

## 7. 持久化与自举边界

HUAB 写入 v4，读取 v1–v4。已有 37 个 intrinsic 从 v3 可读，新增 36 个只在 v4 可读；降低版本后引用新函数 E6002，未知 intrinsic 同样拒绝。
header/payload/opcode 布局保持不变。新值在运行时由标准函数构造，HUAB 不序列化运行中的 Buffer/List 状态，不支持持久化会话。
Native ABI 1/spec 0.1 不变。数据文件不嵌入 HUAB，删除源码后仍需运行时提供数据路径与 Hua/Wasmtime 运行依赖。

本阶段提供扫描源文本字节、存 Token/AST 列表、生成小端字段与 CRC、写二进制产物所需基础。
Hua 版本 Lexer/Parser/语义/字节码生成器/HUAB 编码器、三代编译比较和编译任务资源配置仍未实现；网络/数据库也未启动。
