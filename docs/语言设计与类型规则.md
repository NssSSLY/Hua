# 语言设计与类型规则

更新：2026-10-14。合并当前可执行的词法、语义、值/类型合同和AST/lowering约定。struct+method+interface+composition，不做class继承；显式转换、默认只读借用、Optional/Result保持。

## A01：可解析与可执行的边界

发行能力、自举源码SB1与Hua编译器HC0–HC2输入目标分开维护，见[能力清单](设计决策与未决事项.md#a01-capability-audit)。SB1是内部自举源码准入规则，默认公开CLI不限制到它；不以Hua词法器已有为由声称Parser或编译器已自举。

unsafe块/unsafe函数、ref<T>/ptr<T>类型以及一元取址&保留解析，但当前无完整执行实现。A01将其从“运行到该语句才E4008失败”改为在整个链接程序语义入口E3008拒绝，包括未调用函数及未执行分支；check/interpret/run/build均在用户代码、模块初始化或产物写入前失败。二元按位&保持原语义。examples/unsafe_parse.hua应使用hua ast查看，不能当可运行示例。

Optional<Result>、Map直接Result值、多const、未知属性/标准模块等按现有各阶段诊断拒绝。溢出、nil/错误分支解包、动态只读/类型检查仍是合法程序的运行时诊断，不能承诺静态发现全部错误或撤销前序副作用。这里不开放安全引用、裸指针、extern或复杂FFI。

### 数值：严格模式是统一执行的默认合同

本节冻结新IR、原生后端与合格计算后端必须遵守的设计规则；不是宣布这些后端已经实现。既有VM/解释器仍按上文运行。规则编号用于实现、反例和后续修订，不改变语言版本、运算符或公共接口。

| 编号 | 冻结规则 | 当前落点／验收反例 |
|---|---|---|

| E0-N02 | /是真除法；//向下取整；%与除数同符号或零。零除数E4004；最小signed值除以-1的整除商越界E4002，但余数安全返回0。 | 已实现；-5//2=-3、-5%2=1、5%-2=-1。不得改用截断除法。 |
| E0-N03 | 类别转换与缩窄显式；扩宽及上下文字面量规则保持。浮点转整数朝零截断后检查，移位数量按左操作数宽度检查，非法数量E4005。 | 已实现；i8(-2.9)=-2、u8(1)<<8必须E4005；动态值不能冒充字面量。 |

## E1：Typed HIR 的当前语言子集（2026-10-09）

新IR建立在现有Lexer/Parser、模块链接/语言降级和语义检查之后，不修改公共语法或默认执行器。本节只定义内部E1入口的覆盖边界；外部`hua run/interpret/build`继续支持其他已实现语言能力。

| 构造 | E1当前覆盖 |
|---|---|
| 类型和字面量 | int、float、bool与void结果；支持正负数、已折叠常量、有限浮点及既有数值错误。HIR常量为专用标量variant，不保存AST/运行时对象。 |
| 变量 | let/var/const、显式标量注解、局部与全局、作用域遮蔽、名称赋值/复合赋值与++/--。只读绑定/参数/范围名称不得写入。 |
| 运算 | 标量一元/二元、严格checked数值、比较/布尔、左到右顺序、&&/||短路；不增加隐式类别转换或快速数学模式。 |
| 函数 | 顶层普通函数、标量显式参数、显式单一标量返回、void/省略返回注解的空值函数、已知直接调用与递归。返回值的函数须有标量结果注解；main结果仍不作为CLI退出码。 |
| helper | print只接受int/float/bool；int/float接受一个数值参数，沿用原转换检查。Callable类型仅为内部callee身份，不开放IR函数值参数或间接调用。 |
| 控制流 | if/else、while、int范围for/by/包含终点、一个或两个只读循环名称、break/continue、return。范围零step与边界沿用原Runtime诊断。 |

入口首先通过原语义检查；之后不支持的整段程序在任何初始化之前E8001拒绝，不执行部分前缀、不自动重跑。包括string/nil业务值、精确尺寸/Optional/Result、多返回、容器、struct/interface/enum/match、闭包/嵌套函数、泛型实例化函数、defer、Task、导入模块和外部扩展。它们的旧执行能力保留；这里只限制新IR，未来按独立切片扩展。

E8001表示尚未覆盖的源码/类型/调用；E8002表示内部HIR/MIR的ID、类型、CFG/SSA、effect、作用域/预算记录、大小保护或适配元数据不合法。原前端错误仍原码优先，运行仍使用E400x/E4099等原码。

本阶段保留既有边界：float绑定/参数/返回可以接受符合合同的整数字面量；但当前`var y float=3; y+=2`经前端接受后会在运行期E4003，`y+=2.0`成功。IR对照明确保留此现象，本轮不扩展混合类别算术；后续语义一致性修订需独立合同与回归。

HIR保留类型、只读/写属性、来源和保守effect，MIR保留临时SSA/显式位置读写、checked失败和控制边。完整拥有关系、验证及旧字节码桥见 [运行时E1合同](运行时与扩展设计.md#e1-ir-runtime)；内部演示见 [开发指南](开发与运行指南.md#e1-internal-tool)。


## 词法、注释与语句边界

### 词法输入与标记

Source 先移除 UTF-8 BOM，将 CRLF/CR 规范为 LF；Lexer 验证 UTF-8。

| 标记 | 处理 |
|---|---|
| `/` | Slash；普通真除法 |
| `//` | FloorDivide；所有位置都是整数整除 |
| `%` | Percent；取余 |
| `**` | Power；幂 |
| `/=` / `//=` / `%=` / `**=` | 对应赋值 token；长标记先匹配 |
| `#` | 忽略到换行或 EOF；保留 NEWLINE |
| `##` | 文档单行注释预留；当前按行注释跳过 |
| `#* ... *#` | 普通块注释，可嵌套 |
| `#** ... **#` | 文档块注释预留；当前按块注释跳过，可嵌套 |
| 首行 `#!...` | shebang；忽略正文，保留换行 |

首行 shebang 从去 BOM 后的文件开头识别；其余位置的 `#!` 自然属于 `#` 行注释。
字符串在自身扫描状态内解码；其中 `#`、块标记与 `//` 等均不开始注释。
`/* */` 在字符串外是普通 `/`、`*` 运算符序列，旧注释写法会产生语法错误。
当前不生成文档 token、注释 AST 或文档输出；预留标记的语义已经冻结。

### 块注释状态

优先识别 `#**`（3 字节），否则识别 `#*`（2 字节）；不依赖空格。
进入块后 depth = 1，并记录最外层普通/文档类别。逐字扫描：

1. 遇 `#**` 或 `#*`，压入该层类别、depth 加 1，消费起始标记。
2. 遇当前层对应闭合标记（文档 `**#`，普通 `*#`），消费标记、弹出类别、depth 减 1。
3. depth = 0 时回到普通扫描；遇 LF 发出 NEWLINE；其他字符视为正文。
4. EOF 时 depth 非零，报 E1005 `unterminated block comment`，定位最外层起始位置。

实现为循环与 depth 计数，无递归；混合嵌套另存各层类别，空间随嵌套深度增长。
文档块里的 `*#` 是正文，不能关闭文档层；普通块里的 `**#` 是一个正文 `*` 加 `*#` 闭合。
引号与行注释标记在块内为普通文本，不能屏蔽嵌套块标记。
标记不重叠消费：空普通块写 `#* *#`，空文档块可写 `#****#`；`#**#` 是未闭合文档块。

### Parser 接口与优先级

Lexer 发出代码 token、NEWLINE、End；跳过注释正文。Parser 保留现有 Pratt 优先级：

- `* / // %`：同级、左结合；`7//2*2` 为 `(7//2)*2`。
- `**`：右结合且高于一元运算；`2**3**2` 为 `2**(3**2)`，`-2**2` 为 `-(2**2)`。
- `//=` 与其他赋值同级、右结合；不新增关键字或 AST 节点。

注释保留换行；完整表达式后的换行仍结束语句，`()` / `[]` 内或运算符后的未完成表达式允许换行。
`(7
//2)` 能继续括号内表达式；孤立的 `// old comment` 产生运算符 token 后被 Parser 拒绝。
`1#*x*#2` 保持两个数字 token，不拼成 `12`；`/#*x*#/` 保持两个 Slash，不拼成 FloorDivide。

### 完整示例与易混淆边界（2026-10-05 补充）

```hua
#!/usr/bin/env hua
## 文档标记已预留，当前执行器只跳过正文。
#** 文档块 #* 普通块 #** 内层文档 **# *# **#
let quotient = 7 //#* 与运算符紧邻仍可识别 *#2 # 3
let ordinary = 7 / 2 # 3.5
print(quotient, ordinary)
print("# ## #* *# #** **# // /* */")
```

正常行注释从 # 到 LF/EOF。`##*` 仍是文档行注释，不开启块；
`#**` 一律优先开启文档块，不可作为普通块正文恰好以 * 开头的简写。
需要这种正文时用空白分隔，例如 `#* *正文 *#`。
文件无最终换行也可关闭行注释；块必须显式闭合。
UTF-8 验证作用于整个输入，包括被跳过的注释；无效编码仍报 E1009。

| 写法 | 结果 |
|---|---|
| `#* *#` | 空普通块 |
| `#****#` | 空文档块（不重叠消费起止标记） |
| `#**#` | 文档起始，未闭合，E1005 |
| `#** 文档 *#` | 普通闭合不能关闭文档层，E1005 |
| `#* 普通 #** 文档 **# *#` | 混合嵌套合法 |
| `// old comment` | 整除缺少左操作数，Parser 拒绝 |
| `/* old comment */` | 运算符序列，不构成注释，Parser 拒绝 |

换行不能在注释中丢失。例如：

```hua
fn f() {
    return#*
        注释保留这个换行
    *#42
}
print(f()) # nil；42 是 return 后的另一条语句
```

注释内的引号不构成字符串保护；正文出现 #* 或 #** 就会开启嵌套层。
字符串自身则保护标记，`"#*"` 不需要额外转义，也不启动注释。
文档注释暂不绑定下一个声明、不生成文档、不影响 pub 可见性；文档提取是后续工具功能。
首行 shebang 只被当作忽略内容；Hua CLI 不负责安装 shell 关联或改变操作系统执行权限。

### 模块与 VM 的关系

每个导入文件独立执行同一套 Source/Lexer/Parser 规则，源码位置包含注释所占行数。
注释不进入语义 AST 和 VM 指令；字节码的源位置仍回指原始含注释文件。
check 不运行注释中的文本，run/interpret 输出遵循相同语法；注释标记不会改变模块解析、整除或初始化顺序。
完整可运行边界示例见 examples/comments.hua；带文档块的模块示例见 examples/modules/geometry/package.hua。
前端、运行双引擎与 CLI 测试覆盖这些规则，VM/模块阶段没有重新定义注释语法。

### 扩展语法入口

Map字面量、多返回/绑定与后缀?、interface/enum/match/defer、显式用户泛型及attribute按下文合同执行。标准库不新增关键字，导入沿用限定名/as。
关闭类型实参时可拆分>>或>=；表达式中的移位/比较仍按最长匹配。
async/await/spawn/taskgroup/parallel/simd的受限合同见运行时设计；降级顺序为泛型特化、并发降级、词法降级。

## 基础语义

### 分层

`Lexer → Parser → AST → SemanticAnalyzer → SemanticModel → Interpreter`。
`ast` 不调用语义分析；`check` 运行语义检查；当前 `run` 先经 ModuleLoader 链接依赖，再编译并由 VM 执行。
`interpret` 使用本文的 Tree-Walk 路径进行对照。
SemanticModel 保存模块级函数/struct、方法副作用、推断的已知类型和编译期 const 值。
解析器不执行代码；Value/Environment 不进入 Token 或 AST。

### 作用域与执行顺序

模块函数/struct 可以前向引用。顶层变量与局部变量必须先声明；函数体检查时可见模块所有已声明变量。
若顶层初始化提前调用函数访问尚未初始化的后置全局变量，运行时报告 E4001。
同层重名报 E3002，内层可遮蔽外层；用户模块声明可以遮蔽默认 builtin。

单文件先登记函数/struct，顺序执行顶层语句，再调用 main（存在时）。main 必须零参数。
多模块时先依赖、后入口，模块仅初始化一次，只自动调用入口 main。
若顶层代码主动调用 main，该调用照常执行，不取消之后的入口调用；开发者应避免重复入口调用。
函数环境的父环境为模块环境，不是调用者环境。嵌套函数/结构及闭包使用下文当前合同。
无返回值main仍可直接结束；Result入口的成功/失败映射见 [A06入口合同](#a06-entry-contract)。int、Optional及其他普通返回值继续不作为退出码。

### 可变性和值传递

let/const 不可重绑，var 可重绑；函数参数和 self 不可重绑。
struct 赋值/普通参数传递复制字段值；不会把所有 struct 默认变成共享引用。
Slice 赋值复制 view，访问相同底层元素；切片 O(1)，不深复制。

let 创建只读 struct/视图。复制 struct 可独立修改其值字段，但共享 Slice 字段不会因此获得写权限。
通过只读来源创建 var 别名不能升级 Slice 写能力；clone 明确深复制，产生可变的新数据。
编译期检查能跟踪的只读关系；动态返回值和深层别名由运行时补充检查。

Slice 参数默认只读。`data mut []T`（或已有上下文参数修饰符）要求传入可变参数。
方法采用原规范 §62.4 的初期方案 B：扫描直接 self 写入，并传播已知 self 方法调用的修改效果。
修改方法必须持有可变 receiver，let receiver 会被拒绝。尚未冻结长期显式 mut receiver 签名。

### 基础数值与运算符

int：signed int64；float：有限 float64；bool/string/nil。
int 加减乘、幂、左移、取反最小数等边界检查，溢出报 E4002，不依赖 C++ 未定义行为。
拒绝 bool 隐式真值和普通 int/float 隐式混算。调用未注解函数时由运行时检查实际值。
类型信息不足时 check 可能通过，不代表所有执行路径都已证明正确。

允许可精确表示的整数**字面量**在 float 注解、float 字段、float 参数/返回上下文中取 float 值，
让 Point{x:3,y:4} 这类规范示例可运行；这不允许任意 int 变量静默转为 float。
超过 2^53 的整数上下文转换保守拒绝；显式 float(int_value) 是程序员要求的转换，可有舍入。
float ** int 用整数指数计算，避免巨大指数转换为 double 后丢失奇偶性。
整数负指数暂报 E4005；显式浮点底数可使用负整数指数。

已冻结运算符与注释更新：`/` 真除法、`//` 整数整除、`%` 取余与 `**` 幂。
`5/2=2.5`；`5//2=2`；当前 `//` 对 int 向下取整，所以 `-5//2=-3`。
`//` 与乘法同优先级、左结合，`//=` 对可变 int 绑定/字段/元素生效。
`%` 与 floor division 一致，满足 `a=(a//b)*b+a%b`，余数与除数同符号或为 0。
整除商超出 int64 范围报 E4002；最小 int64 对 -1 取模单独安全返回 0。
普通 `/` 对 int 或 float 同类操作数返回 float；除以 0 报 E4004，不进行 Go 式整数截断。

单行注释为 `# comment`；块注释为 `#* ... *#`，支持嵌套。
`##` 与 `#** ... **#` 分别预留为文档单行与文档块注释；当前按注释跳过，不生成文档或 AST 节点。
文件第一行的 `#!...` 是 shebang，由 Lexer 忽略；其他位置的 `#!` 按普通 `#` 行注释处理。
`//` 在所有位置只表示整除，不再识别为注释；`/* ... */` 不再是 Hua 注释。
Lexer 用 depth 计数处理嵌套，并记录各层普通/文档闭合标记；注释换行保留 NEWLINE。
字符串中的所有注释标记保持字面内容。完整规则见 `docs/语言设计与类型规则.md`。

固定数组物理布局与精确数值使用下文当前合同。
Optional解包和局部控制流收窄见下文；全局/深层字段仍保守。

### const

在语义阶段计算已支持的标量字面量、其他 const 名称、一元/二元运算，执行时取折叠值。
引用 var/let 或使用不支持的调用、容器初始化会报 E3007。
常量短路逻辑只评估需要的分支。check 本身不运行普通函数、不输出 print；当前会读取本地依赖源码，但不执行模块初始化。

### 诊断与安全边界

E3001 未定义名称；E3002 重复声明；E3003 可变性；E3004 类型；E3005 参数数目；
E3006 返回；E3007 常量；E3008 尚未实现的语义结构。
E4001 未初始化；E4002 数值范围；E4003 动态类型；E4004 零除；E4005 运算参数；
E4006 索引/切片；E4007 动态只读能力；E4008 未实现执行能力；E4099 资源限制。
内部E1工具另有E8001（源码不在IR子集）与E8002（非法IR/适配元数据或内部大小保护）；不是新增业务Result错误。

普通诊断保留源文件、行列、片段和箭头。执行中失败前已发生的 stdout 不回滚；
语义检查失败则完全不启动执行。
每次 Interpreter.run 限制 1,000,000 个 AST 执行/求值步骤和 128 层函数调用。
这些是开发期防失控边界，不是时间限制或生产沙箱承诺。

## 值与结果

### 1. Map

```hua
var scores=map[string]int{"Hua":10}
scores["VM"]=20
print(scores.len,has(scores,"Hua"),scores["missing"])
print(delete(scores,"VM"),delete(scores,"VM"))
```

输出为 `2 true nil`，再输出 `true false`。

| 项目 | 冻结规则 |
|---|---|
| 构造 | `map[K]V{key:value,...}`，必须显式初始化；空 Map 为 `{}`，不接受末尾逗号 |
| key | 仅 bool/int/string，同一 Map 严格匹配 K；float/Optional/容器 key 拒绝 |
| value | Map 类型参数 K/V 不变，不把 map[K]int 转为 map[K]int?；条目严格匹配 V，直接整数值字面量可在 float 上下文转换；void 拒绝 |
| 读取 | `m[k]` 为 V?；V 已可空时不重复加 `?`。缺失键返回 nil，不插入 key |
| 存在/删除 | `has(m,k)` 返回 bool；`delete(m,k)` 删除并返回是否存在，要求可写 Map |
| 长度 | `len(m)` 与 `m.len`；值为 nil 的已有 key 仍计入长度，has 可区别缺失和 nil |
| 写入 | `m[k]=v` 可新增/覆盖；复合赋值要求 key 已存在，否则 E4006 |
| 求值 | 字面量按 key、value、下一条目从左到右求值；重复 key 的最后值覆盖 |
| 共享/复制 | Map 共享存储；struct 值按既有复制规则，嵌套 Slice/Map 默认共享。clone 深复制 |
| 可变性 | let、默认参数、循环绑定只读。var 不提升只读来源；`mut m map[K]V` 接受可变 Map |
| 遍历 | `for k in m` 为 key；`for k,v in m` 为 key/value。进入循环时复制条目快照，不承诺顺序 |

快照在进入循环时固定 key 和条目值；循环中新增、删除或替换 Map 条目不改变本轮条目集合。
嵌套容器仍按共享规则，快照不等于深复制。遍历结果不能用于依赖特定顺序的算法。
Map 查找先绑定为局部 let，再判断 `!=nil` 或 unwrap；查找表达式本身不进行重复读取收窄。
Map 值暂不接受直接 Result 类型，因为缺失查找会产生尚不支持的 Optional<Result>；可使用 Result<map[K]V>。
不提供结构化 Map 比较、排序 Map、reserve/cap 或通用哈希 key。

### 2. 多返回、绑定与多赋值

```hua
fn divmod(a int,b int) (int,int) { return a//b,a%b }
let q,r=divmod(7,2)
var a,b=q,r
a,b=b,a
_,a=divmod(10,3)
print(a,b)
```

输出 `1 3`。

- 函数可 `return a,b`，声明 `(T1,T2,...)`；多返回函数可直接转发另一个匹配的多返回调用。
- `let/var a,b=f()` 和 `let a int,b float=1,2` 支持逐项注解；`_` 丢弃该位置。
- 绑定名称不能重复（多个 `_` 可用）；不能多绑定 const，不是通用 Tuple，也不支持调用参数自动展开。
- `a,b=b,a`、索引/字段目标与重复目标可用；重复目标按写入次序由最后一次写入覆盖。
- 先按左到右确定所有目标位置，再按左到右完整求值 RHS，逐项检查并复制全部值，最后按左到右绑定/写入。
- 数量必须相等；已知数量不匹配 E3006，动态数量/类型不匹配 E4003。多值不能整体绑定到一个名称或作为普通参数。
- RHS 的失败/Result 提前返回不会执行本次目标写入；目标求值和 RHS 自身已经发生的副作用不回滚。
- Map 新 key 的目标解析不提前插入。目标保持解析时对应的存储，RHS 中重绑原容器不改变该目标位置。
- 每个绑定独立继承其来源的只读能力；交换可写容器保持能力，与只读来源一起绑定不误伤其他可写位置。

### 3. Result

```hua
fn divide(a int,b int) Result<int> {
    if b==0 { return err("division by zero") }
    return ok(a//b)
}
fn next(a int,b int) Result<int> { return ok(divide(a,b)?+1) }
print(next(8,2),next(8,0))
```

输出 `ok(5) err(division by zero)`。

| 接口/语法 | 冻结规则 |
|---|---|
| `Result<T>` | 等价于 Result<T,string>；自定义错误使用 Result<T,E>，包括具名 struct E |
| `ok(v)` / `err(e)` | 构造对应分支；尚未知的另一侧类型由声明/参数/返回上下文补齐 |
| `is_ok(r)` / `is_err(r)` | 分支检测，非 Result 的动态实参 E4003 |
| `unwrap(r)` / `unwrap_err(r)` | 分别取成功值/错误值；取错分支 E4009 |
| `unwrap_or(r,fallback)` | Ok 返回成功值，Err 返回默认值；默认值类型须兼容 T，并且总会立即求值 |
| 后缀 `?` | 只用于 Result，且必须位于返回单个 Result 的函数内；Ok 解包，Err 返回同一个错误值 |

`?` 要求错误类型兼容，允许调用者使用不同成功类型；返回时保留错误类型/值并匹配调用者的 Result 元数据。
提前返回会清理当前函数作用域、循环迭代器与未完成的 VM 操作数，不执行后续表达式，也不留下未完成的多写入。
`?` 不是 Optional 的空值传播，也不自动捕获 VM 诊断。Result<void,E>已支持无载荷成功；ok()需要明确上下文，不能用nil代替void。详见 [ER1已确认合同](#er1-confirmed-contract)。
Result 的解包、默认值和 clone 遵循 payload 的复制/只读规则；Result 不等于用户可自定义的泛型类。
建议给可恢复错误接口声明完整Result类型；类型上下文中的>=已支持拆分，分开书写仍可用。

### 4. Optional

```hua
fn find() int? { return 4 }
fn main() {
    let x=find()
    if x!=nil && x>0 { print(x+1) }
    print(is_some(x),is_none(nil),unwrap_or(nil,9))
}
```

输出 `5`，再输出 `true true 9`。

- Optional 为 `T?`，直接以 nil 表示空值，非空时保留原 T 的值；`is_some/is_none` 检测是否为 nil。
- `unwrap(x)` 取非空值，nil 报 E4009；`unwrap_or(x,default)` 在 nil 时选择默认值，默认参数总会立即求值；已知 Optional 结果类型用于 nil 分支的默认值转换（例如 float? 默认整数文字按 float 检查）。
- 局部名称（含let、var与参数）可按==nil/!=nil、is_some/is_none及!收窄；赋值同步更新或失效事实。
- `&&` 右侧使用左侧为真时的收窄，`||` 右侧使用左侧为假时的收窄；分支合并保留两路均成立的事实，早退分支按终止情况处理。
- 支持局部名称的while、短路、早退、break/continue与match收窄；全局、深层字段/别名及重复索引读取仍保守，不能外推为完整静态证明。
- Result<T?> 支持可空成功值；Optional<Result<T,E>> 暂不支持，避免无包装表示造成解包层级歧义。
- 不引入独立 Some 包装；重复 Optional 层级不提供独立状态。已知函数结果写能力按固定点推断，未知调用仍保守；独立修改容器时使用clone。

## 语言结构与精确类型

### 接口

```hua
interface Named { fn name() string }
struct Item { value string }
fn Item.name() string { return self.value }
fn describe(value Named) string { return value.name() }
```

结构满足方法集合即实现接口，无 `implements`。参数类型、`mut` 参数及结果签名必须一致；空结果与 `void` 等价。
跨模块只匹配公开方法。接口可以接收满足其方法集合的更大接口；执行时保留具体结构并调用具体方法。
接口不能直接构造，也不能把方法原型当作没有接收者的函数调用。
`mut fn update()` 声明接口可修改接收者；只读方法可以满足可写接口，写方法不能满足只读接口。
接口自身不是继承体系；目前仅结构/接口参与结构符合性，没有标量方法、嵌入接口声明或泛型接口约束。

### 枚举与匹配

```hua
enum Event {
    Text(string)
    Number(int)
    Empty
}
fn describe_event(event Event) string {
    match event {
        Text(text) => { return text }
        Number(number) => { return str(number) }
        Empty => { return "empty" }
    }
}
let event = Event.Text("hello")
```

变体通过 `Enum.Variant(...)` 构造，零载荷也写 `Enum.Empty()`。载荷有位置、数量和类型检查。
枚举在模块层定义，变体用换行或逗号分隔；`pub enum` 同时公开构造函数。
`match` 当前是语句：计算目标一次，按顺序选择唯一分支，载荷绑定只读，`_` 丢弃载荷/匹配剩余情况。
枚举穷尽所有变体或提供 `_`；布尔覆盖 true/false；整数、字符串、Optional 的开放域要求 `_`。
重复分支、未知变体、载荷数量不符、`_` 后的分支均拒绝。限定变体必须属于当前枚举。
所有分支返回可满足函数必须返回的检查。Optional 的 `nil` 分支与后续 `_` 支持收窄。
目前没有 match 表达式、模式守卫、嵌套解构、浮点/负整数模式、泛型枚举或结构比较。
运行时使用私有标签/载荷字段；它们不属于用户字段和 Native ABI。JSON 直接编码枚举返回 Err，需要显式选择应用表示。

### 用户泛型

```hua
fn id<T>(value T) T { return value }
struct Box<T> { value T }
let box Box<int> = Box<int>{value: id<int>(7)}
```

显式类型实参，实例化后检查参数、字段、结果和函数体；支持多参数、递归实例和嵌套类型实参、本地模块导出。
编译时单态化，运行与 HUAB 不需要运行时泛型解释器。单个程序最多 128 个不同实例，防止增长递归。
类型注解紧邻赋值符号时支持 `Box<int>=...`；嵌套 `>>` 在类型上下文拆分。
暂不支持自动类型实参推断、约束/特化/默认参数、泛型接口/枚举/方法或局部泛型声明。
未使用模板不实例化；错误在使用处或被实例化的函数体定位。`a<b>(c)` 按泛型调用解释，比较表达式可加括号消除歧义。

### 局部函数和结构

局部结构具有独立的词法类型身份，具名构造、字段读写、复制、返回和数组元素均可执行；名称只在声明后的作用域可见。
局部函数可以递归、作为函数值返回并在定义作用域结束后调用。
闭包在声明时捕获局部值的只读快照：标量/结构复制，Slice/Map/List/Buffer 保留只读共享视图；`clone` 可取得独立可写副本。
外层局部变量后续重绑不会替换已捕获的标量。模块全局仍是运行时绑定，不是局部快照。
捕获变量不可重绑/修改；局部结构方法和可写引用捕获暂未开放。

### defer 和 attribute

`defer call(args...)` 仅在函数内。声明时计算被调函数和参数；在所属词法块退出时逆序执行。
正常退出、return、break、continue、Result `?` 提前返回和运行诊断都会清理；原始运行错误优先，其他清理仍继续。
无原始错误时传播第一个清理错误。保留执行预算，不提供独立无限清理预算。Windows 的主程序/解释器测试进程保留 8 MiB 原生栈，确保精确值扩展后仍能到达 Hua 的 128 层递归 E4099 诊断。
这是词法块退出规则，不是把所有 defer 累积到整函数退出。

| Attribute | 当前行为 |
|---|---|
| `@entry` | 模块入口零参数函数；与已有 main/另一入口冲突则拒绝，生成转发入口 |
| `@doc("text")` / `@deprecated("reason")` | 检查并保留源 AST 元数据；尚无文档提取器或弃用警告输出 |
| `@inline` / `@noinline` | 已解析的编译提示；当前 VM 未做内联优化 |

attribute 放在函数/结构声明前，重复和冲突拒绝；entry/inline/noinline 仅用于函数且不接收参数。
字符串元数据内部编码，不可伪造 pub/unsafe/external 修饰符。其他 attribute（包括 @fast/@repr(C)/@export）仍拒绝。

### 精确数值

| 类型 | 范围 / 表示 | 字节 |
|---|---|---|
| i8/i16/i32/i64 | 对应二进制有符号范围 | 1/2/4/8 |
| u8/u16/u32/u64 | 0..2^N−1 | 1/2/4/8 |
| byte | u8 范围，保留 byte 类型名称 | 1 |
| int / isize / usize | 当前虚拟机固定 64 位，分别有符号/有符号/无符号 | 8 |
| f32 / f64 / float | 有限 IEEE 754；f32 运算与转换逐次舍入为 binary32 | 4/8/8 |
| bool | 固定数组内 0/1 单字节 | 1 |

同数值类别只隐式扩宽；无符号到有符号需目标更宽。类别转换/缩窄需显式 `i8(x)`、`u64(x)`、`f32(x)` 等。
类型上下文中的字面量可在目标范围内初始化；数组参数/返回/赋值和 Map/Result/多绑定逐元素保留该检查，动态值不享有字面量转换特权。整数目标不隐式接收浮点字面量；`float` 既有整数常量精确表示规则保留。
默认整数字面量仍是 signed int64；完整 u64 可用 `u64("18446744073709551615")`，避免改变旧整数越界合同。
浮点到整数先朝零截断再检查范围；负数转 unsigned 拒绝。字符串转换要求完整、有效、在范围内的数值文本。
同类别不同宽度二元运算选安全较宽类型；右侧字面量可沿用左侧精确类型。算术/移位/转换溢出报 E4002，非法移位报 E4005。
`/` 仍真除法并在整数输入时产生 float，`//` 和 `%` 仍是对应的向下取整合同；unsigned 的整除/余数为非负。
整数幂拒绝负指数；f32/f64 运算拒绝非有限结果。数值标量不是在 C++ Value 内压缩存放，固定数组才使用紧凑布局。
JSON 数值仍限定 int64/有限 float64；超过 int64 的 u64 编码返回 Err。Native ABI 1/WASM 标量签名保持原合同，未新增复杂值或精确数值 ABI。

### 固定数组物理存储

```hua
var values [3]u16 = [1,2,65535]
var independent = values
var view = values[1:]
view[0] = 7
print(sizeof(values), alignof(values)) # 6 2
```

固定数组保留长度和元素类型身份，普通绑定/传值/返回复制元素；`mut [N]T` 借用原数组，默认参数只读。
可写借用要求元素类型一致；固定数组借用要求实参已有固定布局，拒绝把扩宽或临时布局转换误当作原存储借用。只读数值元素扩宽可生成转换副本。
切片仍不复制，保留拥有者、起始位置和长度，且类型是 `[]T`。切片不会因原数组重绑而失去原存储。
数值/bool 以及其嵌套固定数组连续、小端、无元素间填充；例如 `[2][2]i16` 为 8 字节，行优先。
逐字节读写，不依赖宿主未对齐访问。`sizeof(value)` 给出有效布局字节，`alignof(value)` 给出逻辑元素对齐，均返回 int。
非平凡元素（string/struct/Optional/容器）使用连续受管理 Value 槽位；sizeof/alignof 对此反映当前 C++ Value 实现，不能用于可移植 C 布局或 FFI。
单次紧凑存储最多 128 MiB，实际初始化长度仍必须匹配；零长数组允许。不是 native pointer，也没有 stack/arena 分配承诺。
数组、slice、列表转入和 JSON 编码共用元素访问接口，避免绕过布局或只读检查。

### 控制流与跨函数写能力

局部 Optional 的 `== nil` / `!= nil` / is_some / is_none / `!` 与短路表达式支持分支收窄。
覆盖 if/else、早退、break/continue 守卫、match、while 和 for；单/多赋值同步更新或失效原事实。
分支合并只保留双方成立的类型和写能力。循环入口合并零次执行和回边直到类型/写能力稳定，避免把首轮能力用于后续迭代。
模块全局不做局部稳定收窄，避免跨函数重绑使结论过期。
函数返回能力沿已知普通/方法/局部函数、递归调用关系求固定点：新建容器/clone 可写，默认借用参数只读，mut 参数可转发写能力。
方法调用链和把 self 传给 mut 参数的普通辅助函数会传播接收者写效果，并参与接口符合性。
不因为 `var` 别名升级只读容器。推断不明确时保守只读，运行时仍检查真实能力。
这不是所有动态程序的静态证明：未知函数值/动态类型、深层别名/字段路径、泛型约束和返回各位置的独立能力仍有精度限制；全局/字段路径证明与更丰富 effect 类型留待后续。

### 结构复制与共享成员的只读来源（A07-1）

结构值复制后，外层副本可修改；其共享成员仍可能只读。`var b`表示这个副本可重绑和修改自身字段，不保证`b.xs`指向的Slice可写。Result/Optional提取保留这一区别：

```hua
struct Box { xs []int
    x int }
fn main() {
    let r Result<Box> = ok(Box{xs:[1],x:1})
    var b = unwrap(r)
    b.x = 2       # 合法：修改副本的标量字段
    # b.xs[0] = 2 # E3003：共享成员继承了只读来源
    b.xs = [3]    # 合法：给副本替换一个新成员
    b.xs[0] = 4   # 合法：该路径现在指向可写的全新Slice
    print(b.x, b.xs)
}
```

C++检查器与Hua C04记录局部稳定字段路径；根重绑、父字段替换、分支汇合和循环更新这些事实。只在全部可能路径都可写时保留写能力；不能把某个分支的替换视为必然发生。单/多绑定和赋值同样保留成员来源。

本切片覆盖已知结构来源、结果/可选值包装与提取、标准List/Map借用及局部替换。跨函数逐字段返回/写效果、容器内未知别名和混合能力结构字面量仍有限制；不保证所有复杂合法程序都能静态接受。运行时E4007保留，旧HUAB不会因静态规则加强失去动态保护。[范围与正反例](设计决策与未决事项.md#a07-capability-provenance)。

## AST、SourceSpan与降级

AST 是带枚举 NodeKind 的纯语法树，Node 包含 kind、span、text、拥有的 children。
它不依赖 Runtime，也不存储解释执行结果。AstPrinter 输出稳定 S-expression，字符串会转义。

### 子节点约定

| 节点 | text | children 顺序 |
|---|---|---|
| Program/Block | 空 | 源码顺序的语句 |
| Let/Var/Const | 绑定名 | 可选类型，然后初始化表达式 |
| Function | 名称（方法含 owner.），pub/unsafe 标记 | Parameter*，可选 ReturnTypes，Block |
| Parameter | 名称、可选 mut | 可选类型 |
| ReturnTypes | 空 | 类型列表 |
| Struct | 名称、可选 pub | Field* |
| Field | 字段名 | 类型 |
| Import | 点分路径 | 可选别名 Name |
| If | 空 | 条件、then Block、可选 else Block/If |
| While | 空 | 条件、Block |
| For | 空 | 1 或 2 个绑定 Name，迭代对象/Range，Block |
| Range | .. 或 ..= | start、end、可选 step |
| Return | 空 | 返回表达式列表（可空） |
| Break/Continue | 空 | 无 |
| ExpressionStatement/Unsafe | 空 | expression/Block |
| Integer/Float/String/Boolean/Name | 字面文本/解码字符串/名称 | 无 |
| Nil/Omitted | 空 | 无；Omitted 只用于缺省切片端点 |
| Unary/Update | 运算符 | 操作数 |
| Binary/Assignment | 运算符 | 左、右 |
| Call | 空 | callee、arguments* |
| Index | 空 | target、index |
| Slice | 空 | target、start 或 Omitted、end 或 Omitted |
| Member | 字段/方法名 | target |
| Array | 空 | 元素* |
| StructLiteral | 类型名，可含模块路径/别名 | FieldInit* |
| FieldInit | 字段名 | value |
| TypeName | 可点分名称 | 无 |
| SliceType/MutableType/OptionalType | 空 | 类型 |
| ArrayType | 长度字面文本 | 类型 |
| GenericType | ref/ptr/Result/map/List/Task | 类型参数列表；map 为 key,value |

每个节点保留文件、start/end offset、line/column。
范围为半开区间，偏移基于 Source 规范化后的 UTF-8 字节；行列从 1 开始。
括号被折叠到其表达式节点，span 仍覆盖括号。绑定名的语义解析由SemanticAnalyzer负责。
Parser 首错即停止，不输出成功 AST；诊断包含文件位置、源码、原因和箭头，明确时提供 help。
Parser 递归/单段长链上限 192，AST 高度上限 384，超限报告 E2008。
深度和长链限制为开发安全边界，后续可改为迭代实现以支持更大合法程序。

<a id="a05-hua-ast"></a>

### A05：Hua编写的AST内部表示

以上NodeKind/children表仍是现有C++前端合同。A05-1已用SB1验证[NodeId＋List池](../selfhost/ast_pool.hua)和[递归struct对照](../selfhost/ast_direct.hua)，详见[试验合同](设计决策与未决事项.md#a05-ast-pool)。公共AST布局没有冻结；后续C02-P1已实现最小Parser，见下节。

池ID为{pool,index}，只追加、不删除/复用；孩子先于父节点登记，child.index必须小于parent.index。A05时18种enum载荷检查类型与基本元数/位置，子项顺序保持；C02-P1扩到27种，C02-P2扩到59种；新增绑定、类型、容器/结构/枚举/匹配等原有语法载荷。完整自身规模仍受预算限制。来源表保存规范化UTF-8的不可变Bytes，SourceSpan沿用半开字节偏移、1起始字节行列及零宽EOF。

get返回节点记录值与只读子项；修改子项需要clone后replace写回。只读Pool参数静态E3003，当前经Result取得的子项写入运行时E4007；不把运行时能力检查写成完整静态推断。replace保持ID但改变内容；路径复制重写追加新节点并返回新根。所有权、预算/失败、成本、可信字段与缓存失效边界仅维护于上述试验合同，不改变C++ AST、E0数值或错误规则。

<a id="c02-hua-parser"></a>

### C02-P1：Hua前端的最小解析规则

这是内部Hua Parser，公开hua check/ast/run/build仍用现有C++前端。完整范围/预算/排除和源码接口见 [C02合同](设计决策与未决事项.md#c02-parser-slice)，命令见 [开发指南](开发与运行指南.md#c02-parser-usage)。此切片不改语言词法、数值求值或错误/能力规则。

Token增加start/end，均为规范化UTF-8字节半开偏移；原scan与输出kind/text/行列保持。scan_bounded把newline和EOF也计入Token预算，追加前检查。原文数值载荷与原有A05手工数值载荷并存，暂不做转换/溢出/舍入；Parameter允许附TypeName，Function保持Parameters＋Block，在对照JSON中摊平成参数/ReturnTypes/Block次序，内部签名节点不发布但计入池预算。新增Let/Var/Const、ReturnTypes、Break/Continue载荷，仅为当前模块内部表示。

Pratt优先级与C++子集相同：赋值/幂右结合，其他左结合；一元最低12，幂13，因此-2**2为-(2**2)。赋值左侧本切片只允许Name，错误E2007；泛型调用前瞻明确拒绝，不将f<int>(1)错解为比较。支持多行参数/调用与运算符后的换行；保留不带else时if的结束位置，不把后续换行纳入其span。

块/循环/函数维护解析上下文；不在函数的return和无当前循环的break/continue拒绝E2004。语法首错fail-fast，E1xxx与E200x分类/行列对照现有C++；支持外语法E8201，局部预算E8202，内部不变量E8203，文件/命令E8204。它们不是标准Error域，也不改变业务Result默认string。

单类型语法允许int/float/bool/void，语义合法性留C04；仅构造AST不验证名称、签名、数值范围/除零或可变性，输入代码不执行。Token偏移与节点布局、原A05访问能力保持；公共AST ABI、全SB1解析、模块和跨修订分析缓存仍未冻结。

### 模块链接与执行

`ast` 保持原始语法 AST 输出，`geo.Point{x:1}` 的 StructLiteral.text 为 `geo.Point`。
ModuleLoader 克隆并链接 AST：去除已解析 Import、为模块顶层名字添加内部前缀、
将公开导入引用绑定到实际声明，同时保留各节点原文件 SourceSpan。
链接 AST 不覆盖原始文件/AST；前端不负责文件 I/O、pub 验证或模块初始化。
SemanticModel 和内存 Bytecode 使用链接节点的生命周期，执行 API 需保持 ModuleLoader 存活。

### 外部接口与持久化

ExternalInit 是 ModuleLoader 生成的内部节点，text 为外部模块 ID，children 为空；源码 Parser 不产生此节点。
Native/WASM Function 增加 external 标记，保留 Parameter/ReturnTypes 和空 Block，仅用于类型检查和声明登记。
BytecodeCompiler 为其发出 ExternalInit 初始化指令，不编译空函数体；两个执行器通过 ExternalRegistry 调用真实导出。
HUAB 读取只重建最小 Function/Struct 声明及签名，不重建函数体；Code 指针关联到 BytecodeImage 拥有的声明。
函数体执行仍为指令路径；Source 文本只用于位置诊断。BytecodeImage 必须比其 model/bytecode 执行活得更久。

### 值与绑定节点

| Node | text | children |
|---|---|---|
| MapLiteral | 空 | GenericType(map,K,V)、MapEntry* |
| MapEntry | 空 | key、value |
| Pack | 空 | 位置表达式*，仅多返回/多绑定/多赋值场景 |
| BindingList | 空 | 多绑定用 Parameter*；多赋值用目标表达式* |
| MultiBinding | let/var | BindingList、单个多返回调用或 Pack |
| MultiAssignment | 空 | BindingList、单个多返回调用或 Pack |
| Propagate | 空 | Result 表达式 |

Return 保留多个表达式 children，多返回转发为单个 Call；Map 的类型节点与各绑定注解覆盖其完整源码范围。
新节点继续通过原有 span 包含关系检查。HUAB v2 只保存对应指令与最小声明，仍不重建函数体 AST。

### 标准模块与Json

不增加 Parser 节点或标准库关键字。ModuleLoader 为 std.* 生成仅含签名的 Source/接口声明，供导出与类型检查；链接后的执行 Program 不包含这些函数体。
调用链接至内部 `$std$...` intrinsic 名称，两个执行器通过共享注册表执行。std.json.Value 类型别名归一为内建 Json，禁止用户 struct Json 或字段构造。
Value 的末尾新增不可变 Json 包装，Native 原有标量标签不变。RuntimeContext 保存参数、输入流、启动目录，属于运行实例，不序列化到 HUAB。
v3 保存标准函数引用/签名来源，加载时检查已知引用；详细冻结规则见 [基础标准接口](标准库与内建接口.md)。

### Bytes/Buffer/List<T>

Parser 沿用 GenericType，增加内建 List 的已知构造器/单参数检查；不新增 AST 节点或关键词，显式用户泛型按后文lowering处理。
Value 末尾追加 Bytes/Buffer/List 包装，原 Native 标量标签不变。ListData 保存不变元素类型与动态 vector，Buffer 保存共享字节内容；Bytes 为 const 存储。
标准函数签名根据 List 参数推导 T/Result<T>/[]T；未知类型留给运行时，mutates_first/writable_result 参与能力检查。方法效果分析登记直接标准函数对 self/字段的修改。
List 不开放索引目标；snapshot 产生独立 Slice 存储，所以增长不会移动已有 Slice 的元素地址。HUAB v4 保留旧布局，仅新增运行时 intrinsic 合同；不是会话状态序列化。

### 语言结构与lowering

新增 Defer、GenericParameters、Specialize、Interface/Enum/Variant、Match/MatchArm；Attribute 名称已预留，当前属性编码附在声明 text 中（字符串使用 hex 元数据）。
GenericParameters 是模板的首子节点；Specialize 的首子节点是 callee，其后为类型实参。Enum 的 Variant 子节点保存位置载荷类型；Interface 保存 bodyless 方法。
Match 的首子节点是目标，随后为 MatchArm（pattern、BindingList、Block）；Defer 的唯一子节点是 Call。
ModuleLoader 在链接前将 interface/enum 降为带分类元数据的声明；链接后单态化并给局部函数/类型唯一名称。match 在编译中展开跳转，局部函数以 CLOSURE 声明；defer 以 DEFER 保存调用。
SourceSpan 仍指向原始来源；展开节点不代表重写源文件。具体语义与持久化见 [语言结构与类型规则](语言设计与类型规则.md)。


### 并发语法与降级

当前合同：[GC与并发](运行时与扩展设计.md)。Function的async标记、Unary await/spawn、taskgroup块以及parallel/simd循环在泛型特化后、词法名称降级前转换为普通函数/闭包/defer/调用；没有新增持久化opcode编号。Task<T>是新增运行时类型。
await f()?调整为等待结果后传播；parallel范围/步长先绑定一次，再执行单输出纯数值内核。HUAB当前writer6、reader1–6，对新增intrinsic和标准库有版本门禁。此前章节格式号为各阶段历史记录。

## 错误模型的渐进优化提案（2026-10-09）

**状态：供逐项审阅；不是新增已实现语法/类型。** 以 [E0-E01–E06](#e0-error-contract) 为已冻结基线。附件两版错误方案的“已经确定catch”、大写Ok/Err、默认Error、Result<void>和自动成功包装不能覆盖当前代码。旧基线构造为ok(v)/err(e)，默认Result<T,string>；2026-10-09确认后的Result<void>/标准Error已接入，见 [ER1合同](#er1-confirmed-contract)。match是语句且没有Result专用模式，await f()?已按等待后传播降级。

综合决定与ER0–ER4次序见 [设计决策](设计决策与未决事项.md#design-synthesis-20261009)。本节集中候选语义、兼容和验收问题；精确API/关键字及默认启用版本尚待确认。

### 可恢复失败、缺失与运行诊断

| 层级 | 现有合同 | 新设计方向 |
|---|---|---|
| Result<T,E> | 业务/系统操作的预期失败，?传播兼容E；副作用不回滚 | 显式转换、惰性恢复、来源/上下文与忽略操作只作用于此层。 |
| T? | 有值/无值，nil并非失败 | 仍不将表达式?扩展为Optional错误传播。 |
| Diagnostic | 类型、越界、checked数值、预算/取消、模块/产物等运行或编译诊断 | 保持稳定码/来源；不被业务catch捕获。不加入自动throw/try栈展开。 |
| 宿主崩溃 | Native崩溃、强制终止没有语言级恢复保证 | 不包装成普通Err；隔离组件/受控进程另定。 |

网络操作自己的超时/受控取消可由明确新API返回可恢复错误；父Task取消、语言预算与现有await/timeout仍遵守E0。二者通过显式适配衔接，不能以“统一Error”为名把运行诊断全部变成可吞掉的业务失败。

### 标准Error与旧string错误的兼容方向

首版建议新增**明确写出Result<T,Error>**的标准错误类型；模块名、公共字段/方法与内存形状待审。不改变Result<T>当前默认string，不自动解析所有旧英文message猜分类，也不为所有自定义E引入隐式转换。

| 候选信息 | 约束与待决定项 |
|---|---|
| domain＋code | 稳定机器身份，区分语言E诊断码与应用/宿主错误域；无新诊断码在本轮分配。 |
| kind、message | kind做粗分类，message可本地化；开放错误域须兜底，不以字符串文案判断身份。 |
| cause、secondary | 主原因与清理/并发附属错误分开；限制长度/深度/总字节和循环，内部链可共享不可变节点，但必须接入GC/复制规则。 |
| context、origin | 显式操作描述与可选SourceSpan；按失败路径补充，?默认不打印，不每层捕获完整backtrace。 |

旧接口保留Result<T,string>；新接口可在冻结时选择Error，或提供明确适配入口。转换时保留原错误，不声称只有一个code便可无损还原宿主错误。若未来改Result<T>默认E，必须独立版本提案、迁移工具与旧源码/产物兼容验收；不以类型别名偷偷更换。

领域库仍可返回Result<T,DomainError>；封闭enum可以在现有match范围内检查变体覆盖，公共开放Error须有兜底。材料的Err(Error.NotFound)嵌套匹配涉及Result模式与嵌套解构，均不是当前match已支持内容。

### 组合函数先行，语法便利分别审阅

优先通过候选std.result等**普通函数入口**实现map_err、惰性恢复、context和显式ignore；模块/名字/泛型约束另定。材料的.method形式需要Result方法分派能力，不能假定已有。map_err显式E→E2，仍返回Result；context只支持所声明的Error或明确转换；ignore不打印、不重试，仅丢弃已返回Result，调用本身的Diagnostic仍传播。

未处理Result先检查直接丢弃表达式及保存后完全未使用的局部值，报告定位与处理提示；再提供显式strict模式或版本化错误。赋给变量只表示暂存，不证明已处理；返回/传给具有明确处理责任的API可转移责任。首版不承诺所有别名/全局/容器路径的must-use证明。明确ignore可带理由用于审阅，不必增加关键字。不能第一天让所有旧工程因新增硬错误无法运行。

Result<void,E>已按 [确认合同](#er1-confirmed-contract)实现：成功无载荷，错误E不变，void不能成为普通可用变量；ok()仅在明确上下文构造，?成功继续执行而不制造nil载荷。已覆盖函数返回、Task、动态检查和HUAB对照；物理布局不作为公共合同。Result<T?>的nil成功仍与Result<void>无载荷成功区分。

自动ok包装是独立便利性候选：仅在明确Result返回边界、表达式静态等于T且无歧义时考虑；已等于目标Result则直接返回，err原样，赋值/参数不隐式包装。嵌套Result或部分类型未决时要求显式ok，避免把一个错误Result误当成功载荷。先确定Result<void>和上下文检查，再决定是否启用；不得额外引入隐式数值/错误类型转换。

### catch作为惰性Result恢复候选

```text
以下仅为待审阅形状，不是当前可运行语法：
result_expr catch fallback
result_expr catch issue => recover(issue)
```

候选规则：左侧求值一次；Ok取成功值，完全不求值fallback；Err时才绑定错误/调用fallback，恢复值须兼容T。只恢复Result，左侧/恢复逻辑的Diagnostic照常传播；不回滚已执行副作用，不自动重试。返回类型为T，若要继续返回Result应显式构造或选择组合函数。

不能改unwrap_or的立即求值合同来实现catch。优先级/结合性、与?及await的括号、跨换行解析、错误绑定作用域需单独冻结；首版建议要求混合或链式写法加括号。现有await f()?的语义保持；不能重新把?应用到Task本身。块表达式、隐式末行返回、嵌套模式与catch块内return另有成本，第一版不一并增加。

先比较惰性函数/现有if、match与新catch的可读性收益，再决定是否增加关键字。若采纳，须Lexer/Parser/AST/lowering/sema、两执行器、HUAB/IR支持矩阵和工具同步，不能只改语法高亮。

### 来源、入口报告与资源清理

传播不等于记录日志：?只返回Err。标准Error在失败时可按策略添加有界调用位置；generic E不被擅自改写。成功路径检查/分配和错误路径大小需实测；Debug/Release可调整信息量，稳定错误身份与行为保持。

Error Boundary是**新的显式入口/宿主协议**：识别入口Result，清理完毕后成功退出0，失败stderr报告一次/非零；HTTP/Agent宿主可映射成自己的响应。当前main返回值不自动改变退出码；旧脚本打印Err仍可能正常结束0。先定入口签名/Result<void>/模块初始化/Task结束和格式，显式启用或版本化，不静默改变旧CLI。

一般defer规则保持E0：?返回是正常返回，defer Diagnostic可取代业务Err；原Diagnostic优先，其余清理继续尝试。新增托管资源组合器可在自己的Result协议保存主Err＋secondary；成功但必要flush/close失败应返回清理Err。defer不能保证强制终止或预算耗尽时完成，也不默认允许异步清理挂起。

固定数组源码尺寸只允许 `0` 或 `[1-9][0-9]*`，即 `[0]int`、`[2]int`、`[20]int` 等普通十进制写法。`[02]int`、`[0_2]int`、`[00]int`、`[2_0]int`、`[0x2]int`、`[0o2]int`、`[0b10]int` 在Parser阶段E2006拒绝，包含参数、字段、嵌套数组及Result/Map中的尺寸；在任何初始化副作用前失败。普通数值字面量的进制/分隔符不受这条数组规则影响。每维0..1000000、零长和尺寸数值身份保持；类型元数据和type查询统一十进制，尺寸不是const表达式。此规则由用户在A02之后明确修订，取代此前允许多种尺寸源码拼写的方案。合法旧HUAB尺寸元数据的数值兼容只属于读入规则，不能用于放宽源码语法。

可静态确定的直接/嵌套数组字面量长度不匹配，check/build/run/interpret在任何初始化前E3004拒绝；动态Slice或未注解结果转固定数组仍按实际长度E4003。合规十进制的过大尺寸E3004；不合规拼写先由Parser以E2006拒绝。复制、Slice视图、小端布局、非平凡Value槽及128MiB单次紧凑存储上限保持。

```hua
fn second(xs [2]int) int { return xs[1] }
fn main() {
    let xs [2]int = [1,2]
    let number i8? = 1
    let result Result<i8?> = ok(2)
    print(second(xs),type(xs),type(unwrap(number)),unwrap(unwrap(result)))
}
```

输出 `2 [2]int i8 2`。直接数值字面量上下文可穿过Optional以及Result的Optional成功类型；普通变量仍遵循扩宽/显式缩窄和类别转换规则。超范围字面量在执行时E4002检查，不宣称check会折叠所有常量。/、//、%、f32逐次舍入和有限值/范围合同不改。

`nil`是缺失值；`void`表示没有普通可用值。单一无值函数返回、`Result<void,E>`成功、发行`Task<void>`成功可使用void；普通变量、参数、字段、数组/Slice/List/Map元素、`void?`及多值位置不可使用，E3004。枚举空变体的内部void标记不代表开放void载荷。Result<T?>的`ok(nil)`与Result<void>的`ok()`保持区别；后者成功解包不能绑定为一个nil值。

普通声明仍要求显式初值；struct漏字段E3004，后置全局提前读取E4001，不提供默认零值。`Result<Result<T>>`、显式Result<void>嵌套可用；Optional<Result>和直接Map Result值仍拒绝。多返回按位置检查/转换，所有检查成功后才写入，动态失败不产生部分写入；通用Tuple、展开、默认字段、late init、Some、隐式ok/catch未加入。

## A03-1 容器与嵌套字面量的基础语法（2026-10-13）

Array、Map和具名struct初始化体使用明确的闭合符号；其内部表达式不继承外层if/while/for头部的块消歧上下文。因而循环容器、Map值、struct字段中可以直接使用已有的空struct构造 `Empty{}`，无需额外加括号。退出字面量后恢复外层头部上下文：`if flag {}` 中的 `{}`仍是语句块，不能吞为类型初始化。

## A06：公开入口结果与失败边界（2026-10-14）

用户确认保留最简单的无返回值main；需要传播失败时可显式采用Result<void>，需要机器分类时显式采用Result<void,std.error.Value>。不强制所有入口返回值，不把int自动变成退出码，不自动包装ok、不新增catch。

```hua
fn main() {
    print("Hello, Hua")
}
```

上例正常完成由运行器退出0。需要可恢复失败时使用既有语法：

```hua
fn work() Result<void> { return err("input failed") }
fn main() Result<void> {
    work()?
    return ok()
}
```

main仍是可选的零参数自动入口；依赖main、显式调用main和普通函数的Result继续作为普通值，不提前结束进程。只在运行器自动入口结束后解释最终单一Result：Ok退出0，不输出成功载荷；Err输出stderr并退出非零。推荐Result<void,E>；已有Result<T,E>也按同一分支规则处理，成功载荷不成为stdout或退出码。main返回int/Optional/其他类型仍保持旧行为。

Result<void>仍等价于Result<void,string>。string Err默认退出1，原消息展示，不根据消息中的E编码/关键词猜退出类别。std.error.Value Err复用error.format的身份、message、origin、context、native码、cause和truncated展示；不改错误数据，不隐式把string/领域E转成Error。领域enum/struct等E默认退出1，仅报告类型，避免隐式完整载荷日志；详细报告须由程序显式格式化或适配。

| 最终结果/根错误身份 | 退出码 |
|---|---|
| 正常无返回值/无main脚本/Result Ok | 0 |
| string Err、普通业务Error、hua.cli.input或其他hua.cli code | 1 |
| std.error.Value根身份hua.cli + usage | 2 |
| std.error.Value根身份hua.cli + internal | 3 |

hua.cli是选择CLI结束类别的显式约定，只检查根节点身份；cause和message不改变类别，其他domain即使code相同也默认1。它不是权限标识，也不会把Error代码当任意数值退出码。

入口函数的defer/Result传播与运行结束Task/File清理全部完成后才报告Err；业务Err仍是正常返回，不取消既有正常结束清理。defer诊断可以替代Err，先发生的运行诊断仍优先；未观察Task的诊断同样优先于入口Err，不吞预算/取消诊断，不回滚前序副作用。async main沿用已有入口自动await，最终await值是Result时按同一入口规则报告；普通Task的Err仍是值，普通await不因此新增错误映射。

宿主CLI的0/1/2/3及E0001–E0004只查 [命令报告](开发与运行指南.md#a06-public-entry)。入口失败的E0003位置指向自动调用的main定义，现已增加有界的Err创建/?传播来源note，完整调用栈仍未冻结；见[A10来源合同](#a10-source-contract)。check/build不执行main，也不把main中的业务Err误作编译失败。[实际验收](项目概览与进度.md#a06-entry-verification)。

## A08：模块名称与可见性

<a id="a10-source-contract"></a>

## A10：源码位置与失败来源（2026-10-15，当前范围已验收）

Source按既有合同去掉UTF-8 BOM，并将CRLF/CR规范化为LF；SourceSpan.start/end是这份规范化UTF-8字节流的半开区间，line/column从1开始，column仍是字节列。范围端点限制在源码内，反向范围折叠为空；EOF有合法零宽位置。Lexer、Parser、lowering和指令保留原文件来源，不改为字符列或UTF-16列；编辑器继续在展示层换算。

本切片保持fail-fast：一次检查/构建失败报告首个Diagnostic，不执行输入，也不替换已有输出。消息中的控制字符与非法UTF-8仍转义；只有诊断文件、字节位置和行列与待展示Source相符时才展示片段，不能拿入口文件替代导入文件。

AST与VM在实际表达式/指令处补齐原先无文件的Diagnostic，并保留code、message、help；函数调用与模块依赖增加来源note。defer注册后的调用错误统一指向实际调用表达式。自动main失败仍按A06分类和退出，业务Err额外记录创建和?传播来源；该来源是内部有界元数据，不改变公开Error字段、Result<T,E>类型或打印/恢复语义。

跨AST、源码VM与无源码HUAB比较完整stderr；定位独立按Python规范化字节参考核对。31例1157项公开检查与68项原生检查通过，详见[实际结果](项目概览与进度.md#a10-diagnostic-verification)。多诊断聚合、Parser恢复、warning/lint、JSON诊断与完整调用栈仍属独立设计。

<a id="a07-field-effects"></a>

## A07：有界成员来源、返回与写效果（2026-10-15）

混合结构字面量逐成员记录能力，返回结构、Result/Optional包装及多返回每个位置沿用各自来源。外层及嵌套值型结构的副本可修改标量字段；继承的Slice/Map/List等共享后代继续只读，整体替换成员或clone可建立新能力。固定数组普通值复制保持来源能力，独立存储不自动表示可写。

已知普通函数/方法/可解析函数别名具有返回成员摘要、成员写要求和写后事实。调用会检查被写成员，并同步成员替换、全局重绑及共享容器后代在已知别名中的事实；分支、零次循环与return出口共同合并，不能用只发生在一个分支的刷新证明后续写入安全。defer的记录值快照不把私有字段替换反向应用到调用者。

原生95例／1423检查、65项分析器复用检查，以及C04 150例／2226检查（含1153项节点事实对照）通过。成员视图与函数写效果均最多8层，函数摘要最多32轮；深层写入使最近保留祖先失去深层所有权，未收敛摘要清除未经证明的写后事实并保守处理返回各位置、全局和可变实参。未知对象图/条件相关性的精确证明没有成为新的语言保证；动态E4007保持。

Hua C04已同步并通过AST/VM/HUAB/SB1小输入对照、独立原生节点与函数元数据核对；T1排除的方法、非string错误、未注解回调和嵌套函数仍只在原生矩阵验收。多返回转发与重新赋值保留每位置能力；标准可变操作和delete的成员写要求沿辅助调用传递；临时容器实参仍同步既有别名的后代事实。新建存储按当前调用重新实例化，实际共享的存储继续保留身份。

结构字面量只继承实际初始化项的成员事实，不能从类型默认形状虚构空容器的可写后代。Result标量包装与枚举构造的能力标记、深层投影及缺失成员来源与原生一致；类型/参数数量错误优先由既有类型检查报告，不被新能力检查或内部unwrap失败遮蔽。报告schema保持`hua.types.capabilities.v1`。[本轮验收](项目概览与进度.md#a07-field-effect-verification)。
