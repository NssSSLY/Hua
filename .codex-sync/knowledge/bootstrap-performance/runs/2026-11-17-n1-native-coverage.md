# N1 本地后端覆盖与性能（2026-11-17）

## 基线与改动

- Windows，perf/vm-register-r1@a4eec89ef0c4a3296feb80904a0c41cfb538eab0，项目本地 Clang 23，生成程序使用 C++20 和 -O2。固定语料为 132 个标准库基准、7 个核心基准和 27 个示例文件。
- 实参、索引的标量和句柄在求值时保存。多值通过带类型的返回包和位置绑定，保留记录参数在实参求值结束时的快照时机。多重赋值支持名称目标。
- 函数目标静态已知时生成直接调用。不逃逸的闭包环境放栈上，其余可具体定型的环境有独立生命周期。标量、可静态复制的纯记录和部分共享容器已覆盖。同步算法、List、Heap 和 Map 回调使用带类型调用，保留回调顺序、工作限制和 List 版本检查。
- Deque、Heap、Set 和随机操作直接处理带类型数据。VM 与本地后端共用随机核心。File 通过现有控制块保持位置、关闭状态和错误合同。Result 的无载荷成功按既有规则传输。
- 生成代码的 HUA_NATIVE_COUNT_STEPS 编译期开关控制计步。原型差分驱动默认计步，发布矩阵使用不计步模式。溢出、边界和调用深度检查仍执行。

## 验证与限制

- 生成基线为标准库 102/132、核心 7/7。发布模式的最终矩阵为标准库 132/132、核心 7/7、示例 22/27。用各自的临时目录隔离文件基准。日志只替换 UTC 时间戳，algorithms_config 只替换实际计时，其他内容及退出码一并比较。全部基准另核对各自 .expect。
- 早期失败包括无载荷 File Result、Optional 收窄后的 unwrap C++ 编译错误和临时目录干扰，已针对根因修复并重新对照。原始路径及日志在 tests/artifacts/n1-20261117。
- 示例缺口仍为 language_features 的精确数值及其固定数组和接口路径。同时记录两个依赖 N2 的并发示例、一个缺扩展清单二进制的示例和已被 VM 前端拒绝的 unsafe_parse。
- 通用动态函数类型、复杂且可能成环的闭包共享图、多重赋值的成员和容器元素目标还需实现和边界核对。本轮不关闭 N1。

## 修复记录与性能

基准按 Windows 同机串行交替启动，包含进程启动时间。关闭计步版本在第一轮 139 项的中位加速为 3.30×，落后 VM 的五项做七轮复核。对复现项修复后，使用同一输入比较 VM、保留的旧本地程序与最终本地程序。

| 修复 | 影响与实现 | 修复前本地 | 修复后本地 | VM |
|---|---|---:|---:|---:|
| 循环拼接 | 独占字符串直接追加，共享值仍按值复制 | 58.43 ms | 7.89 ms | 47.60 ms |
| Map get_or/pop | 删除后搬移稠密条目并修补探测链，避免每次删除重建整个索引；按需排序 | 80.83 ms | 11.92 ms | 71.41 ms |
| 文本 last_index/count | 按字节搜索，空模式按既有规则处理，直接使用带类型字符串 | 68.73 ms | 15.86 ms | 57.21 ms |
| 字符串模板 | VM 与本地端共用占位符解析，本地 Map 按字符串视图查找 | 36.60 ms | 12.49 ms | 35.63 ms |
| trim/ASCII 大小写 | 直接处理带类型文本，保留 ASCII 语义和容量检查 | 141.56 ms | 17.28 ms | 140.77 ms |

36 个本地程序与 VM 差分一致，1 个不支持的 Task 程序按合同拒绝。file_bulk、deque_heap、random_crypto、language_structure 定向检查通过。单项原始采样保存在 performance-all.json 和 hotpaths.json。
