# Windows N2 Task 收拢结果优化

2026-11-20。基线为 perf/vm-register-r1 的 5d206c4。Windows 11 x64，Clang / CMake Release，Python Bridge 和内部性能计数关闭。优化前后都用 tests/build-n2-windows-20261118 构建。先保留基线宿主与静态库，再更换 Task 运行时。原生基准关闭计步，HUAB 使用 compiler 执行配置。

## 实现与兼容

- 隐式退出收拢、taskgroup 退出、all / race 的收尾共用已有等待路径，保留取消、超时、终态、清理、输出和错误的处理。成功且可安全丢弃的结果只做只读检查，省去深复制。
- 首片支持标量以及由这些值构成的普通 Slice、List、Map、Result 树。深度超过原限、固定数组、记录等无法由首片证明的结果进入原复制路径，保留原诊断。显式 await 与 timeout 的成功值继续复制给每位等待方。
- C++ 专项覆盖 taskgroup、整个执行域的退出、all 与双方已成功的 race。两个隐式收拢的目标堆新增受管分配均为零。all 的组合堆只分配 19 个对象，race 只分配 9 个，分别对应两棵保留结果加组合外层、以及一棵胜者结果。副本独立、输出只交付一次、不可复制的宿主值继续报 E4003。
- file_stdlib、task_resume_single、task_resume_migration、task_resume_public 共 4 项通过。单 worker 435 个断言，双 worker 441 个断言。native_backend 通过，103 个程序与 VM 一致，12 个超出范围的程序正确拒绝，用时 75.98 秒。

## 实测

每次进程创建四个后台任务，各返回指定行数的 List<[]int>，其中每行含两个整数。等四个任务进入终态再开始记录收拢耗时，端到端计时仍包括进程启动、数据构造、输出及退出。2 worker。每格先热身，再交替执行基线和候选，各 12 次。输出逐行检查，HUAB 两侧运行同一文件，原生两侧生成的 C++ 逐字节相同。

| 每 Task 行数／路径 | 端到端中位数（ms） | 收拢中位数（ms） |
|---|---:|---:|
| 5,000／HUAB | 74.99 → 53.23 | 17.81 → 1.22 |
| 5,000／Windows 原生 | 42.84 → 29.79 | 14.64 → 1.09 |
| 25,000／HUAB | 271.37 → 185.26 | 84.76 → 6.52 |
| 25,000／Windows 原生 | 157.04 → 83.06 | 77.08 → 5.15 |
| 75,000／HUAB | 949.29 → 616.30 | 326.08 → 19.18 |
| 75,000／Windows 原生 | 679.85 → 342.55 | 355.61 → 16.80 |

75,000 行另跑各 5 个样本，用 n2_windows_bench.sample 每约 2 ms 查询 Windows 进程峰值工作集。中位数为 HUAB 261.14 → 220.46 MiB，原生 246.30 → 215.86 MiB。这组单独采样的耗时未纳入上表。大结果负载端到端下降 35.1%／49.6%，高于方案建议的 25% 门槛。显式取回结果、难以证明可丢弃的数据和其他负载的收益以各自实测为准。

## 复现与证据

在 Windows 上把基线和候选各自的 hua.exe、libhua_semantics.a、libhua_frontend.a 及运行所需的 DLL 准备好。运行：

```powershell
python tests/tools/n2_task_join_bench.py <baseline-hua.exe> <candidate-hua.exe> <new-output-dir>
```

本机的原始逐次数据和生成源文件在 tests/artifacts/n2-task-join-20261120/paired，计时为 report.json，内存为 memory.json。基线宿主 SHA-256 为 f3375684c63b2cedaf9a3db06de33a6ee71f4b23e861721d2e4200c4a4a99fbb，候选为 00c7687d326378e7f6876d9525f9b525bae2a990c68eb5889fa7fceb8e12bb4f。完整自举和其他平台不属于本次测量。
