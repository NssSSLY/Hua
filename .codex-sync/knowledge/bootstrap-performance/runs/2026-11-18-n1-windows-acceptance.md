## 同步动态边界

- 源接口已装入动态值时，按实际接收者的具体类型检查目标接口。双向转换通过。具体类型不兼容时保留 E4003，诊断与 VM 一致。可写实参保存原接收者别名，经动态间接调用仍写回原对象。
- 无静态类型的字段读写、方法、Slice 或 Map 索引、切片和遍历由本地后端拒绝。已有退出码 2 和源位置诊断。带静态容器参数的路径由既有差分用例覆盖。
- 未注解的 Optional 或 Result 取值和判定，以及依赖带类型实参的标准库路径，在生成 C++ 前拒绝。审查前已在 Optional 的 unwrap、Result 的 is_ok 和 unwrap、List 的 len 复现过 Clang 编译失败。未定型的动态容器可先归入明确的参数类型。VM 支持的同步动态操作范围仍大于本地后端。
- 修复后本轮独立盘点 29 例，10 例执行行为与 VM 一致，14 例由本地后端明确拒绝且没有 C++ 产物，5 例为宿主前端拒绝。项目差分套件通过 87 项 VM 对照和 12 项拒绝检查。

原始输出、完整产物、脚本及 SHA 记录位于 tests/artifacts/n1-windows-20261118，机器摘要见 selfhost.json、final.json 和 dynamic-final/report.json。当前范围为 Windows 两项验收。其他平台按用户要求暂缓。此处确认的是现有 Hua 编译器通过两个执行后端生成同一 HUAB 的闭环，N4 的自生成原生编译器仍在路线中。
