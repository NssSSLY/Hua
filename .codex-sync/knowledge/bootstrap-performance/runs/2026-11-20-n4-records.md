# Windows N4.2A 字符串、结构体与模块初始化

2026-11-20。从 N2 验收的 C3 构建 Hua 生成器，再以固定 Clang/lld 与 Windows Release 运行库生成原生 EXE。

- C05 提供结构体身份和模块执行顺序。生成器先按字段类型依赖安排布局，再执行顶层绑定和语句，最后调用入口。全局变量的存储保留未初始化状态。
- 字符串字面量按真实 UTF-8 字节数生成，内嵌零字节参与比较、拼接和长度。结构体在复制、参数与返回边界传递值。赋值先定位并保留字段所在的记录，再求值右侧，支持右侧重新绑定外层变量和临时结构体字段。
- 最终冻结源码由 C3 构建用时 247.634 秒，在 600 秒监督限额内。生成器为 HUAB 格式 17、4,047,265 字节、60,444 条指令，SHA-256 为 `e0dae59d806dd42256dc40c91ea691acce92f0853d49d29015d256e7ccf543cc`。
- 七组新用例和四组标量回归通过 AST、源码 VM 和移走源码后的 EXE 差分。两组生成拒绝用例分别保留已有 C++ 和 EXE。各成功生成的 C++ 与宿主快速构建的生成器逐样例同哈希。
- 覆盖菱形导入、跨模块结构体返回、复制隔离、字段初始化求值顺序、右侧替换外层结构体、临时结构体、中文与零字节、仅顶层代码、未初始化全局量 E4001 和初始化失败 E4004。故障比较错误码、主源码行列、退出码及停止前的标准输出。E4001 的原生消息使用全局绑定通用文本。
- 快速构建的生成器先通过五组用例。新探测发现 AST 接受临时结构体字段赋值，初版生成器在计算接收者时拒绝该用法。最终版通过现有 `RecordStorage` 钉住字段所有者，加入该用例及未初始化全局读取的回归。本轮两个冻结构建和探测结果都保存在同一实验目录。

复验使用 `tests/tools/n4_records_acceptance.py <hua.exe> <generator.huab> <new-output-dir> --scalar`。原始输入指纹、归档构建回执、生成的 C++ 和差分报告位于 `tests/artifacts/n4-2a-20261120/` 下的 `final-inputs.json`、`final-bootstrap.json`、`final-c3/`、`final-verified/`。

下一片 N4.2B 接入 Bytes、Slice、List、Map、索引位置、复合赋值和范围循环。接着用 Result 传播与词法器所需的实际标准库签名完成 N4.2C。完整编译器原生化与代际闭环分别进入 N4.3 和 N4.4。
