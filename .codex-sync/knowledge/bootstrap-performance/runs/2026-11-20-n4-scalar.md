# Windows N4.0／N4.1 首阶段验收

2026-11-20。使用 N2 验收的 C3 种子、仓库固定的 Clang 与 lld、既有预编译 Hua 运行库。输入 SHA-256 与实际版本见 tests/artifacts/n4-first-20261120/acceptance/inputs.json。验收对冻结的 selfhost 副本执行。

## 编译入口与实施

- Hua 入口先执行名称、类型和写能力分析，然后读取验证后的 C05 Core，在 Hua 中生成带类型的 C++。整数规范化与 C07 共用。C++ 使用既有原生数值、诊断与入口运行库。
- 首片覆盖 int、bool、void、普通函数、递归、局部绑定和简单赋值、分支、while、break、continue、直接调用、print。支持整数加减乘、向下整除、余数及标量比较和布尔短路。直接调用及二元表达式的实参按 Hua 顺序求值。
- Windows 开发驱动向归档传递 emit，随后通过既有 Clang 链接参数生成临时 EXE，整条链路成功后才替换目标。驱动执行宿主的 run 子命令加载 Hua 生成器。样例 EXE 的符号表中可见运行库入口 hn::run_main、hn::print。
- C3 构建首个生成器耗时 308.762 秒。首次探测在 List 模块初始化遍历处被自举类型系统拒绝，改用 C06 已有的 snapshot 遍历方式。最终归档 SHA-256 为 432822cea452318f46f5b397399938cfb0093a0ea650dbd4ab9764be121dcdba。

## 差分和变更证明

- 四个程序统一对照 AST、源码 VM 和脱离源码的 EXE。覆盖求值顺序、短路、循环退出、分支、遮蔽、递归、多进制、整数极值、除零及溢出。错误码、主源码行列、退出码和标准输出一致。
- 字符串输出与顶层副作用两个用例均在生成阶段拒绝，既有 C++ 和 EXE 字节均保留。
- 在冻结副本仅替换加法生成规则，C3 重建生成器耗时 353.948 秒。同一 print(9+4) 的 C++ 只有调用 hn::add 或 hn::sub 这一处差异，EXE 输出 13 → 5。
- CTest 的既有原生后端通过 108 个差分和 13 个拒绝用例。现有 C07 开发入口生成的无源码 HUAB 也通过有符号极值及多进制字面量复验。
