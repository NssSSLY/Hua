# Windows 跨语言基准（2026-11-18）

## 测试环境与口径

- Windows 11 x64（26200），Intel Core i5-11300H，4 核 8 线程。同一台机器串行启动基准；Hua 0.1.0-dev 使用 N1 Windows 验收后的 Release 构建。Lua 5.4.7、CPython 3.12.0、Java HotSpot 25.0.2、Go 1.27.1、C++ 与 Hua 原生均由 Clang 23.1.2 以 -O2 构建。C++／Go 为各自工具链的本地程序。
- 正式端到端每格运行 7 次，取中位数。子进程逐轮轮换顺序，另有未计入统计的预跑。Java 先发现 PATH 指向启动代理，随后直接执行 JDK 的 java.exe 单独采集 7 次，表中使用复核结果。每次校验数值输出及退出码，共 406 个计入统计的样本。5 门参照语言和 Hua 的源码 VM、HUAB、原生覆盖全部七组。
- 端到端时间包含新进程启动、加载、执行及退出。源码 VM 含前端和字节码生成，HUAB 路径含加载与校验，原生可执行文件预先构建。文件读使用同一 4 MiB 夹具，属于本机已访问的文件缓存条件。
- 内存是 Windows 单进程 PeakWorkingSetSize 的中位数，包括运行时、代码页、堆与驻留映射。它有别于堆分配量和 Java 的最大堆参数，CPU 时间及每次原始采样在本机记录中。
- 容器实现采用各语言常用表示。Hua 测 `std.list`，Lua 为 table，Python 为 list，C++ 为 vector，Go 为 slice，Java 为 long[]。Map 使用字符串键与整数值，容器的实现与分配策略各自保留。本文衡量相同工作负载在这些具体实现中的实际成本。

## 进程预热后的内核

在同一进程先运行一遍完整输入并核对校验值，再由测量器通过管道触发三次略有不同的等价计算（参数 n−1、n−2、n−3）。下表计时从触发到读回校验值，包含很少的管道开销。每格五个独立进程样本，合计 80 个正式样本；进程启动、加载、预热均在计时区间之外。Lua、Python、Java、Go、C++ 与三条 Hua 发布/VM 入口均对照通过。

## 观察与限制

1. **循环和递归。** 预热后，Hua 原生对 Lua 约快 2.3 倍和 8.7 倍，对 CPython 约快 17.1 倍和 24.4 倍。按相同方式对照 HUAB，原生约快 3.3 倍和 12.0 倍。原生与 C++ 同量级，仍分别慢约 1.23 倍和 2.58 倍。Java 与 Go 在这两个预热用例也领先 Hua 原生。
2. **容器与文本。** 30 万项整数容器中，HUAB 需 589.60 ms／58.9 MiB，原生为 27.86 ms／10.8 MiB。这个工作负载最能显示 Hua VM 中容器和值的综合成本，具体分配及拷贝占比仍需剖析。文本拆分的 HUAB 为 426.85 ms，原生为 92.95 ms，Go 为 40.03 ms。
3. **轻 I/O。** 4 MiB 读取和间隔取样中，Hua 原生用 37.26 ms，Lua 25.91 ms、Go 18.65 ms、C++ 15.90 ms。该用例同时含进程启动、一次读文件和少量取样计算，数值适用于这组本机条件。
4. **AST 单独中断。** 默认 AST 配置在三百万次循环触发 E4099，正式对照统一使用已有的 compiler 配置。AST 的整数循环中位数约 5.83 秒，首次运行 fib(30) 达到 60 秒硬限，没有输出，监督器终止并跳过后续 AST 项。该实现对树节点递归求值，基准提供结果与症状，调用、分配和表达式调度各自占比未测。VM 和原生的相同递归都成功完成。正式未重跑完整自举。
5. **排序的适用范围。** 表中只比较现有七组单进程负载。端到端短程序受启动和装载影响明显，预热结果也只覆盖整数循环及递归。原生 N2 并发、网络、真实数据库及大型应用需要各自的多轮负载。
