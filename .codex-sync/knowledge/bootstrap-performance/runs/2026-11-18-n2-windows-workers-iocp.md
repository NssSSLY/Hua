# Windows N2 Task 控制、多 worker 与 IOCP（2026-11-18）

基于 perf/vm-register-r1 的 51e0061 与上一批容器快照。Windows x64 LLVM-MinGW Release。原生性能产物关闭计步，功能回归继续使用默认计步原生构建。

## 已实现和核对的范围

- 已知声明且捕获类型在当前数据范围内的原生闭包可启动 Task。复制闭包环境和已初始化模块槽，子任务保持只读绑定。挂起 defer 的清理由所属 Task 逆序完成，挂起前退出 C++ catch。栈分配闭包一旦用于这类 defer，其环境延长到清理完成。
- taskgroup、cancel、done、state、timeout、all 和 race 复用既有 TaskRuntime。保持 timeout/all 只接受有值 Task 的宿主合同。Hua 前端接入顶层 spawn、taskgroup 和 std.task。
- 原生首次调度设置 worker 归属，之后在该 worker 恢复。VM 无栈帧保留跨 worker 迁移。初始化后共享的字面量哈希和标准库分发表为只读。
- Windows 后台任务的 File 普通与批量读写接 IOCP。任务挂起时释放 File 互斥锁，资源事件继续保留 File 和缓冲区。取消请求使用 CancelIoEx，完成由内核通知确认后退休。打开、元数据、flush、close 仍走既有宿主路径。Hua 前端接入 std.file，普通 File 引用根据已有标准库版本生成 HUAB 8，批量读写生成 HUAB 29。
- 原生差分 103 个通过，12 个子集外用例按预期拒绝。完整的原生自举编译器与 VM 比较，共五个指定输入的输出、诊断、退出码和产物一致。File 对照矩阵含 AST、源码 VM、宿主 HUAB、Hua 自举 HUAB 及原生，两种后端各跑五组。同样检查文件内容、逻辑游标、EOF、关闭、软超时和 Task 清理。持久化路径运行前移走源文件。

## 同机性能

固定 8 个计算任务、合计 2,000 万轮。各配置 7 次交替采样，校验值一致，每次核对使用的 worker 数和纤程挂起前后线程身份。

| worker | 中位耗时 ms | 样本 P95 ms |
| ---: | ---: | ---: |
| 1 | 95.24 | 154.43 |
| 2 | 54.60 | 73.18 |
| 4 | 37.80 | 53.81 |

文件负载固定为 8 个任务各读 16 MiB 缓存文件，4 个计算 worker。计时为进程启动到退出，包含打开、关闭和结果检查。每项 7 个样本，P95 取近秩。线程和工作集为进程运行期间的采样峰值。

| 比较项 | 阻塞池 | IOCP |
| --- | ---: | ---: |
| 中位耗时 ms | 31.35 | 25.88 |
| 吞吐 MiB/s | 4083 | 4946 |
| 样本 P95 ms | 85.82 | 41.85 |
| 峰值线程 | 16 | 17 |
| 峰值工作集 MiB | 9.80 | 10.07 |

第一轮 32 MiB 文件负载的 IOCP 进程样本没有采到线程和工作集。原记录保留，表中采用相同路径延长至 128 MiB 后的完整采样。当前程序级取消测试可观察到 canceled 和清理完成，未单独强制驱动进入内核取消与迟到完成之间的指定竞态。

huaBin 已更新并核对 24 个清单项，保留上一版完整 SDK。源标准模块搬移检查通过。原始过程在 tests/artifacts/n2-remaining-20261118，固定负载入口为 tests/tools/n2_windows_bench.py。
