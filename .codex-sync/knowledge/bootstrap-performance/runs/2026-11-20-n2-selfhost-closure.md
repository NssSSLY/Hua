# N2.3 Hua 自举局部闭包修复

2026-11-20。基于 5d206c4 及已验证的 N2 本地优化。历史反例中，Hua 解析器在局部 fn 处返回 E8201，编译入口把它归到 types 阶段。这次把普通局部函数贯通到 HUAB。局部函数可作为普通调用和已知声明的 spawn 目标。运行时沿用声明时的捕获及 spawn 时的隔离，两者保留不同的时机及共享视图语义。

## 实现

- 扩展解析模式允许函数体内的普通 fn。C03 给声明分配块级身份，进入函数体前建立自身绑定。局部 async fn 和局部结构仍在该切片之外。
- C04 在声明处按捕获环境检查。外层局部值按只读投影，循环和 return 的作用域独立。局部调用使用保守效果，避免将一份捕获环境的写能力推广到其他调用。
- C05 保留局部函数角色，C06 为声明生成 Closure 加不可写 Bind，C07 按原 HUAB 函数元数据写 nested 标记。C06 检查闭包目标和逻辑引用，完整作用域和捕获能力来自 C03/C04。独立的 C05/C06 传输工具同步处理嵌套声明。

## 实际验收

- 最初反例的四路输出一致。宿主 AST、宿主 VM、自举 HUAB、Windows 原生均输出 6，退出码均为 0。自举归档和原生可执行文件在移走目标源码后运行。
- 自举前端通过 10 个正例和 13 个反例。覆盖捕获标量重绑、捕获容器在 spawn 前后的两次修改、任务模块状态、局部递归、两层闭包、同名声明遮蔽、越出作用域、捕获写入以及循环退出边界。
- 独立 C05 与 C06 传输分别验证逻辑节点、闭包元数据、归档输出和无源码执行，均输出 6。
- 原始产物及日志在 tests/artifacts/n2-selfhost-closure-20261120/。原反例结果为 original.json，两种传输分别为 C05.json 和 C06.json。首次候选被 C05 节点角色验证拒绝，随后补齐角色检查复验通过。

## 完整自举

从已通过闭包用例的 C1 开始，用相同的冻结源码生成 C2 和 C3。分别用时 254.482 秒和 246.491 秒，每代执行 1,230,737,201 步，峰值 52 层。两代均通过 10 项正例、13 项反例及宿主归档校验。产物逐字节一致，为 HUAB 17、4,477,856 字节、66,813 条指令，SHA-256 为 701cf2b23447954135f184499585ea60620e4c5d2c06e8088c8f8f177af491ed。逐代回执及预算见 bootstrap.json。

C06 传输负例移除 nested 标记后仍保留原闭包指令，验证器拒绝。适用范围为普通局部函数及直接 spawn。嵌套 async fn、结构体与枚举等更广原生载荷按各自合同继续验收。
