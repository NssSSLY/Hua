# Windows N3.3 原生发布缓存验收（2026-11-23）

基于已验收的 N3.1／N3.2 发布入口和 N4 原生生成器。Hua 模块解析器记录实际读取的文本和按优先级检查的导入路径，Hua 发布驱动校验源码与产物 SHA-256，并管理整次 EXE、C++ 对象和链接结果三级复用。复用对象须匹配生成的 C++ 与有效编译输入，复用 EXE 须再匹配链接输入。缓存和用户产物通过独立暂存文件原子发布。

首版逐文件读整个工具链后，一次普通构建花了 24.730 秒做输入校验。最终采用 Windows 本地 NTFS 批量枚举目录和比较文件标识、变更时间、大小。更新内容后恢复普通修改时间仍会失效。运行库与实际选用的生成器继续核对内容摘要。Windows Clang 使用随包的显式配置。遇到无法确认的外部工具配置时走常规构建。

| 负载 | 冷构建 | 命中后构建 | 生成、编译、链接次数 |
| --- | ---: | ---: | --- |
| 发布 SDK 的 Hello | 5.247 秒 | 0.404 秒 | 1／1／1 → 0／0／0 |
| 包入口导入 | 3.773 秒 | 0.394 秒 | 1／1／1 → 0／0／0 |
| `std.alg_integer` | 4.313 秒 | 0.397 秒 | 1／1／1 → 0／0／0 |
| 完整 Hua 原生生成器 | 415.461 秒 | 0.529 秒 | 1／1／1 → 0／0／0 |

完整生成器的冷构建中，生成 C++ 用 74.353 秒，Clang 用 338.776 秒，链接用 0.737 秒，缓存校验用 1.344 秒。热构建删除输出后实测，校验用 0.388 秒，恢复用 0.133 秒，EXE 的 SHA-256 与冷构建一致。恢复出的生成器成功生成样例 C++。这次冷构建长度低于 600 秒上限。历史 N3.2 的构建使用了不同版本源码，本轮还与 SDK 装配部分重叠，其耗时需要按运行条件分别解读。

黑盒验收覆盖修改传递依赖后恢复普通修改时间、`foo.hua` 遮蔽 `foo/package.hua`、SDK 源码标准模块变动、头文件同大小同修改时间改写、静态运行库切换、损坏 EXE 和对象恢复、缓存不可用、输出被锁定和并发写入。更换真正改过规则的 N3.2 候选生成器后，探针从 `13` 变为 `5`。重生成的 C++ 字节相同时，实测跳过了 Clang 与链接。仅切换静态运行库时，实测跳过了 Clang 编译并重新链接。

原始回执位于 `tests/artifacts/n3-native-cache-20261123`。功能验收用临时装配 SDK，规模实测用隔离 SDK 和共享只读工具链。首轮装配收尾遇到 Windows 目录发布占用，加入有界重试后完成正式装配。正式安装位置两模块样例冷／热为 5.402／0.411 秒。独立运行输出 `2 2`。保留旧 `huaBin` 用于回退。

接续 N3.4 模块对象缓存与依赖失效。N3.3 仍按单个 C++ 翻译单元处理生成结果变化。
