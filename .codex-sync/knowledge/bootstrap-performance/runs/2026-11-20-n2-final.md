# Windows 原生发布 N2 整体验收

2026-11-20，在 5d206c4 及同日 N2 性能修改的工作树上完成。Windows x64，Clang Release。最终宿主 SHA-256 为 a299c5e8d1a41e2bfe6911bbef5853d12874b159177833e5b5023fe0b29dc724。同源数据、源码清单、逐轮时间和产物保存在 tests/artifacts/n2-final-20261120/shape-order-fixed/。

## 实施与语义核对

- 普通结构体和枚举递归检查全部字段与变体。启动方快照参数、闭包捕获及可达模块槽，运行时只复制枚举活动分支。显式 await 复制结果，后续等待仍独立。File、Buffer、循环名义类型及超过 64 层的原生载荷按受限合同拒绝。
- 宿主词法降级和 Hua 自举 C02–C07 均接入捕获外层值的局部 async fn。支持直接递归和 spawn 递归。函数体内把自身当作值报 E3008。Hua 自举 async main 仍在当前自举子集之外。自举前端完整收集名义字段后再校验结构字段上的 Task 注解。
- 在真实 Windows 命名管道上提交 32 字节的重叠读，不写入数据。ReadFile 返回 ERROR_IO_PENDING。通过 Task 取消使 CancelIoEx 成功，并拦住对应 IOCP 通知。放行前 Task 非终态，一个文件、一个操作以及 32 字节在途额度得到保留。收到 ERROR_OPERATION_ABORTED 后确认一次退休，观察到 E4101，句柄关闭，全部额度归零。命名管道只用于宿主夹具。生产 std.file 继续面向普通文件。
- native_backend、file_stdlib、task_resume_single、task_resume_migration、task_resume_public 共五项 CTest 通过。原生差分 108 个一致，13 个生成前拒绝。文件专项有 35 场景、188 次检查。Task 恢复专项为单 worker 452 次、双 worker 458 次检查。
- 用最终 C3 对照七个同源程序、五条执行路径，共 35 次比较。依次检查 AST、源码 VM、宿主生成且无源码的 HUAB、Hua 生成且无源码的 HUAB、Windows 原生程序。覆盖结构体、枚举及其模块槽、捕获式局部异步递归、容器和包装值、控制和清理。故障用例五条路径均输出 cleanup 并报告 E4004。
- 独立开发入口的 C05 lower、C06 emit 已发布局部异步递归报告。C05 从报告还原 AST 和 VM，C06 从报告还原指令，均输出 6 5 40，C05/C06 的宿主指令投影一致。Python 校验器此前误将生成节点按源码节点投影，且 C06 的类型与内建表漏了 Task。修正后通过正常命令。一次临时诊断使用 40 秒上限而中断，正常验收采用已配置的 600 秒预算。
- 真实普通文件读写的阻塞池和 IOCP 矩阵覆盖五条路径。实际文件字节相同。公开取消例允许合同规定的竞争结果，确定在途取消由上面的专门夹具覆盖。

## 600 秒完整自举

宿主用 49.327 秒从源码构建 C1。C1 运行生成 C2 用时 247.777 秒，C2 运行生成 C3 用时 251.964 秒。三代各通过 14 个正例、17 个反例和宿主归档校验。反例验证不覆盖既有产物。

C2 与 C3 逐字节相同，为 HUAB 17、4,526,681 字节、67,504 条指令。两代均消费 1,259,199,828 个预算步，峰值调用深度为 52。SHA-256 为 5c22ade895ec1680e64f1d33de2fdc567f4b33aedef0ee587482a9eb99d7731a。

初版候选已通过代际检查。额外对照发现，同一个不符合自举载荷规则的 Task 字段注解在字段表未填充时可能被错误接受。补正反顺序用例后重新冻结源码。五路径脚本最初的除零错误码期望写为 E4005，按实测更正为 E4004 后通过。前一轮已经完成的单次规模耗时用于参考，长链路数据与短任务性能采用各自的工作负载。

## 性能

原生 8 个定长 CPU 任务，在 1／2／4 worker 下的中位数为 134.25／98.49／66.46 ms。实际用了指定数量的 worker，挂起前后线程归属一致。4 worker 的中位速度为 1 worker 的 2.02 倍。

同一 128 MiB 缓存读文件负载，阻塞池到 IOCP 的中位数 50.57 → 39.70 ms，降幅 21.5%。吞吐 2531 → 3225 MiB/s。7 个样本的经验 P95 为 146.09 → 63.33 ms。峰值线程数为 16 → 17，峰值工作集 10.85 → 10.46 MiB。均含进程启动及退出，适用于本机缓存负载。

| 交替 A/B 工作量 | 基线中位数 / ms | 最终中位数 / ms | 降幅 |
|---|---:|---:|---:|
| 32 个短 Task，只读取模块中的一个槽 | 32.51 | 21.60 | 33.6% |
| 16 万次 yield，1 worker | 130.51 | 71.66 | 45.1% |
| 16 万次 yield，4 worker | 134.25 | 71.33 | 46.9% |
| 16 MiB，4 KiB 缓存读，1 worker | 58.99 | 56.08 | 4.9% |
| 16 MiB，4 KiB 缓存读，4 worker | 36.90 | 34.62 | 6.2% |
| 四个 Task 各返回 75,000 行，HUAB | 841.58 | 571.76 | 32.1% |
| 四个 Task 各返回 75,000 行，原生 | 536.45 | 268.87 | 49.9% |

所有 A/B 使用相同输入、交替 12 对且校验输出。模块、yield 和缓存读的基线宿主为 00c7687d326378e7f6876d9525f9b525bae2a990c68eb5889fa7fceb8e12bb4f。收拢的基线宿主为 f3375684c63b2cedaf9a3db06de33a6ee71f4b23e861721d2e4200c4a4a99fbb。收拢区间只看规模最大的一档，HUAB 283.15 → 19.61 ms，原生 271.40 → 15.16 ms。此区间是在任务均完成后、作用域收尾处测量；端到端包含产出数据的成本。

复验入口在 tests/tools/n2_windows_bench.py、n2_task_followup_bench.py、n2_task_join_bench.py、n2_task_final_acceptance.py 和 tests/selfhost_async_tests.py。报告发布复验可用 n2_task_final_acceptance.py 的 --frontend-reports。原始记录分别保存于 windows-matrix/report.json、paired/report.json、join/report.json、five-paths/report.json 和 bootstrap.json。
