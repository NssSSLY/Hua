# Windows Hua 源码直接运行与原生运行（2026-11-24）

Windows SDK 新增 hua run --release <file.hua> [-- args...]。宿主调用现有原生发布驱动，在独立临时目录生成或恢复 EXE，然后以调用者的当前工作目录和终端句柄启动程序。退出码原样交付，正常结束或构建失败均清理临时目录。普通 hua run 保持源码 VM 路线，hua build --release 交付普通应用的独立 EXE。

同机每组七轮，记录包含进程启动和读取标准输出的墙钟中位数。源码 VM、HUAB 和已有 EXE 数据来自接入命令前的 N3.5 SDK，同类程序输出一致。300 万次循环使用 compiler VM 配置以容纳步数。

| 输入 | 源码 VM（毫秒） | HUAB VM（毫秒） | 已有 EXE（毫秒） |
| --- | ---: | ---: | ---: |
| Hello | 16.875 | 15.746 | 7.722 |
| 3 万次整数循环 | 21.814 | 16.541 | 8.365 |
| 300 万次整数循环 | 63.477 | 59.430 | 17.787 |

新增命令在解压后的 SDK 上另测七轮。冷运行使用空应用缓存，热运行复用同一次构建。

- Hello冷运行 906.107 毫秒，热运行 190.961 毫秒。
- 300 万次整数循环冷运行 1005.024 毫秒，热运行 216.284 毫秒。

最终 ZIP 包含 5,128 个受清单记录的文件，文件大小 125,870,983 字节，SHA-256 为 45b9710bc1844e36fe9d3ca513d9e432f46bd6cc918b5c40ad2aedb9c80e5c98。Unicode、空参数、引号、反斜杠、工作目录、失败退出码、缓存共享和临时目录清理均在搬移副本通过。原 Windows SDK 发布回归与 os/process 的 63 项检查通过。正式路径 huaBin 安装后，源码 VM、原生直跑和独立 EXE 输出一致。

证据位于 tests/artifacts/n3-5-local-run。测量负载的整数循环为 state = (state*48271)%2147483647，循环后只输出一次结果。
