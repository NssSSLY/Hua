# Windows N3.1／N3.2 原生发行验收（2026-11-23）

基线为 `perf/vm-register-r1` 的 `71bca6941fbf71ef7d735613eaa9b2305b7b45b9`。装配输入使用 N4 已验收的第 C 代 C++ 生成物和归档编译器 C++ 生成物，与本轮支持 Windows UTF-8 参数的新运行库链接。生成器和归档编译器分别耗时 303.954 秒和 301.250 秒。发行包内 16 个编译器 Hua 模块与 N4 冻结输入的 SHA-256 一致。[N4 验收](2026-11-21-n4-full-entries.md)

## 发行结构

- `bin/hua.exe` 从自身路径找到 SDK，并把 `build --release` 分发到 Hua 驱动 `lib/compiler/release.huab`。原生编译器目前拒绝 `std.process`，探针返回 `E8201`，因此发布编排由宿主 VM 执行。生成程序的解析、类型检查、降级和生成 C++ 仍由 Hua 原生生成器执行。
- 使用阶段只调用包内宿主、生成器和编译工具。SDK 随附固定 Clang 23.1.2/lld、头文件和预编译静态库。源标准模块继续从根清单注册，工具链清单单列，防止根清单超过现有源码模块加载限额。
- 原生生成器、归档编译器与本轮生成的常规应用 PE 只导入 Windows 系统库。宿主的 Wasmtime DLL 随 SDK 保留，供宿主执行路径使用。
- 宿主读取了随包的种子、HUAB 28 的发布驱动，以及独立原生归档编译器为多模块样例写出的 HUAB 6。完整同源归档的 HUAB 17 证据来自 N4 历史验收。

## 仓库外验收

把 SDK 复制到包含中文和空格的仓库外路径，清除 `HUA_HOME` 和 `HUA_PATH`，子进程 `PATH` 只保留 System32。按清单逐文件校验 SHA-256 与大小。Hello、多模块和源码标准模块的 EXE 单独复制到运行目录，读取 PE 导入表，并核对输出。源码错误、错误扩展名、缺少 lld、输出 EXE 被锁定均以非零退出码结束。错误分支保留原 EXE 并清理临时文件。

候选版用包内 Hua 源码构建。在隔离副本中把整数加法对应的生成操作改成减法，经既有生成器生成候选编译器。随后以正式发布命令对同一探针构建并运行，原生成器输出 13，候选版输出 5。完整构建受 600 秒总预算约束。

最终安装目录 `huaBin` 再次构建两模块示例并输出 `2 2`，首次用时 7.666 秒。修复缺发布驱动时中文路径的诊断编码，更新宿主和重新验证种子后，正式目录复跑耗时 2.715 秒。最终包再次在仓库外通过 5,122 个文件的清单校验、应用独立运行、HUAB 与中文缺依赖诊断。不含根清单的发行体积为 414,414,610 字节，最终报告见 published-sdk-report.json。候选构建保留来自 N4 的两条 C++ 穷尽枚举分支返回警告，待后端为非法标签补充明确终止路径。

现有进程库 63 项检查与文件系统 61 个场景共 357 项检查均通过。Windows CMake 配置生成成功。每项耗时来自一次本机运行。SDK 搬移和独立运行均在同一台 Windows x64 机器的隔离目录验证。

原始回执、诊断、导入表和 SHA-256 位于 `tests/artifacts/n3-native-sdk-20261123`。仓库中可用 `tests/windows_release_sdk_tests.py --sdk huaBin --work <仓库外新目录> --readobj <llvm-readobj.exe> --rebuild` 复验。旧种子 SDK 保存在该结果目录下的 `previous-huaBin`。
