# Windows N4.2D 至 N4.4 实施记录

## N4.2D 复核与 Parser 验收

- 冻结的 N4.2B／C 工作树中，归档入口和生成器入口分别有 60,744、57,170 个 C05 节点，75、60 个内建调用标识。共同首阻断为 ast_pool.hua 中的合成枚举构造。
- Hua 后端接入 C05 的枚举布局和构造身份，并用同一标签做 match 分发，支持可写结构体借用、多绑定、浮点、位运算和归档入口使用的 defer 与 Buffer 操作。C04 用到的结构相等复用现有运行时比较语义。
- 核验时扩展 Parser 的小预算曾令真实输入全部返回 E8202。改用编译器预算，核对 lexer、ast_pool、parser 源码的完整语法树，分别得到 1,668、2,627、7,517 个节点，原生与 VM 回执相同。非法输入 E2001 也一致。
- 以当前 Hua 后端处理此前冻结的两个入口，分别产出 6,221,236 和 6,084,911 字节 C++。两份完整翻译单元均通过 Clang 类型检查。
- C3 已在 303.662 秒内生成对应的 VM 基准归档，4,526,917 字节，67,504 条指令，SHA-256 为 55269168d0f23ca58f769e6116b11b82c24d94f91b842bc1a6393ca7bf4f4c56。
- 驱动增加直接运行原生生成器的选项，以独立目录装载运行库。已经从现有开发生成器成功生成并运行标量 EXE，记录了实际执行者。代际验收仍以正式 A、B、C 的完整输入为准。

原始证据位于 tests/artifacts/n4-d-20261121。parser-compiler-report.json 保存真实语法树对照。archive_main.json、native_main.json 保存初始依赖盘点，两个 clang 日志保存完整 C++ 类型检查。

## N4.3 原生归档编译器

原生 archive.exe 编译同一冻结归档入口用时 52.946 秒，VM 基准用时 303.662 秒。两份 HUAB 的 4,526,917 字节完全一致。归档由宿主独立检查通过。移走编译器源码后，该归档编译了另一份多模块程序，移走该程序源码后仍输出 42。

原生与 VM 的缺失导入 E5001、模块预算 E5005 和文件发布 E8204 回执一致，保留先前产物并清理临时文件。两条路径共用 C07 的格式 17 和 ABI 1。时间是一次同输入端到端编译的对照，构建原生编译器的时间单列。

当前 Hua 生成器本身由 C3 重建用时 302.987 秒。正式原生代际验收在独立测试目录运行。

同一份冻结 VM 编译器再编译同源用时 307.588 秒，继续得到相同 HUAB。Python 独立核对了 32 字节头、版本、ABI、长度和 CRC32。

## N4.4 原生代际闭环

| 代际 | 生成 C++ 耗时 | Clang 编译与链接 | 总耗时 |
| --- | ---: | ---: | ---: |
| 种子 → A | 278.844 秒 | 198.781 秒 | 477.641 秒 |
| A → B | 42.359 秒 | 227.313 秒 | 269.703 秒 |
| B → C | 55.984 秒 | 244.672 秒 | 300.703 秒 |

- A、B 由驱动直接调用执行 emit。独立运行库目录只有所需 DLL 与静态库，构建回执记录了上一代 EXE 的路径和哈希。
- 三份生成 C++ 逐字节一致，SHA-256 为 e221d1e1ebeceb5ebb30b7001565543286aea3de5bbbb87b9271f923ff040679。PE 原始哈希有差异，单独清零 COFF 与调试目录时间戳后哈希一致，为 f7ccd9a1a7ef865916eb4c69c86c38ce2a566ced926b55dcb2e12b0a4331cfb3。
- 原生 B、C 构建的两份归档编译器分别产出完整 HUAB，均与 N4.3 VM 基准逐字节相同。两代生成的多模块样例结果一致，未定义名称诊断与旧产物保护一致。
- 一条加法生成规则改动经 A 构建进入子代。指定样例从 13 变为 5，生成 C++ 仅待验证表达式的一处调用有差异。无算术样例生成的 C++ 保持逐字节一致。

原始证据集中于 tests/artifacts/n4-d-20261121/n4-final-report.json，保留冻结源码和原始产物。仓库内可用 tests/tools/n4_generation_acceptance.py 复验。

Hua 原生生成器和 HUAB 编译器的 Windows 闭环已验证。固定 Clang/lld 继续负责机器码生成，底层运行库仍参与链接。后续沿 N3 进入可搬移打包和构建缓存。
