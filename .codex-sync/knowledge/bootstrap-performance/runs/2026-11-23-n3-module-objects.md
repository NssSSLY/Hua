# Windows N3.4 模块对象增量发布（2026-11-23）

同一 Windows 机器，LLVM-MinGW Clang 23.1.2，原生生成器从 `selfhost/native_main.hua` 构建。旧 N3.3 SDK 以单翻译单元在 429.105 秒内构建含 N3.4 实现的种子，其中 Clang 359.052 秒。该种子用于冷构建、随后使用新构建的生成器验证下一代。原始回执在 `tests/artifacts/n3-module-objects`。

| 场景 | 总用时（秒） | Hua 生成（秒） | Clang（秒） | 编译对象数 |
| --- | ---: | ---: | ---: | ---: |
| 整个生成器冷构建 | 385.679 | 78.823 | 304.508 | 13 |
| 删除输出后的整次命中 | 0.564 | 0 | 0 | 0 |
| 切换到生成器子代重做同源生成 | 59.888 | 58.554 | 0 | 0 |
| 词法器私有实现变动 | 70.031 | 59.369 | 9.008 | 1 |
| 真实 Token 字段改动 | 128.088 | 76.061 | 50.118 | 2 |

子代启动后重新生成全部模块，13 个对象和 EXE 均命中。增量构建后的词法错误随改动发生变化，真实布局探针让 Parser 读回新字段构造的 `E2001@77:10`。完整源码仍走同一 C04 与 C05 链路。热构建已恢复同哈希产物。

正式装配的 SDK 通过 5123 个清单校验。独立发布回归覆盖 EXE／对象损坏、同修改时间内容变化、导入遮蔽、运行库切换、失败保留产物、并发发布、旧生成器回退、共享布局、枚举顺序与初始化顺序。小项目三模块冷构建 12.943 秒，同一缓存下只改叶模块时 4.135 秒，整次热命中 0.460 秒。本轮功能套件与规模冷构建部分重叠，小样本的冷耗时单独记录。

早期探针暴露了只读 List 不能直接追加，最终利用 C05 连续节点区间消除分组复制。首次 Windows 菱形夹具的断言以 LF 比较原始 CRLF，修正为文本模式后完整回归通过。这两项证据分别留在 `seed.stderr` 和 `function`。

## 同机同源码对照

用相同的生成器子代构建同一次词法器编辑。传统单翻译单元以关闭缓存方式测得 398.737 秒，其中 Clang 332.932 秒。模块增量为 70.031 秒，其中唯一的 Clang 编译 9.008 秒。端到端加速 5.69 倍，缩短 82.4%。进程树合计 RSS 的采样峰值从 2,126 MiB 降至 234 MiB。采样 RSS 可能重复计入共享页。

模块冷构建对照用时 374.916 秒。其 EXE 与缓存增量构建的 SHA-256 均为 `4168d768cb533f87363813cfb6c64d9f643a90c36d1056df09ccb4f272ee07be`。增量、干净分模块与单翻译单元构建出的编译器对同一正确样例生成相同 C++，对非法字节给出相同诊断。干净构建与真实布局对照有部分重叠，耗时作为流程记录。当前样本的 PE 字节一致，N3.5 仍负责不同发行条件下的 PE 复现。

两模块程序关闭缓存，以单／多／多／单顺序测两次。单翻译单元中位 3.622 秒，多单元中位 8.754 秒。小项目额外支付模块和入口各自启动 Clang、解析头文件的开销。完整生成器的局部增量中，Hua 全程分析、降级和生成占 84.8%。N3.5 优先处理小项目首次构建与发行验证。

最终 SDK 已安装到项目的 huaBin，旧 SDK 保存在本轮产物目录的 previous-huaBin。正式路径两模块样例冷构建 10.020 秒、热构建 0.393 秒，EXE 输出 2 2。规模对照后增加了每个对象的复用诊断字段，最终驱动重新检查归档、校验 5123 个清单文件，并通过叶模块命中及重编原因回执。
